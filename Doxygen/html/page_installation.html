Introduction

PB3D is written in Fortran and is built with CMake. It makes use of the following external libraries:

  • MPI
    • for the parallel processes
  • PETSc / SLEPc, built with complex scalars
    • for the large, sparse matrices of the eigenvalue problem and for its solution
  • MUMPS, through PETSc
    • for the distributed LU factorization in the eigenvalue solver, which is needed to run PB3D on more than one MPI process
  • HDF5, parallel and with Fortran bindings
    • for the output files
  • NetCDF-Fortran
    • to read the output of VMEC
  • BLAS / LAPACK and ScaLAPACK
    • for dense linear algebra, in particular the boundary-element system of the vacuum, which PB3D solves with the LU factorization of ScaLAPACK (pdgetrf and pdgetrs)
  • LIBSTELL, part of the STELLOPT suite, which contains VMEC
    • to read the output of VMEC (PB3D uses only the module read_wout_mod)
  • PSPLINE
    • Princeton Spline and Hermite Cubic Interpolation Routines

Furthermore, PB3D comes bundled with some other, smaller libraries, which CMake compiles with the code:

  • fftpack (Libraries/dfft.f)
    • to calculate the fast Fourier transform
  • foul (Libraries/foul.f90)
    • the Fortran Output Library
  • test-drive (tests/vendor/test-drive)
    • the framework of the unit tests

PB3D can be obtained using git: 

git clone https://github.com/ToonWeyens/PB3D.git

The commands below use two shell variables. PB3D_SRC is the directory of this clone, and DEPS is a directory in which the dependencies that are built by hand are kept. 

export PB3D_SRC=$PWD/PB3D
export DEPS=$HOME/pb3d-deps
mkdir -p $DEPS

Requirements

The build needs the following tools:

  • A Fortran compiler and a C compiler. The builds that are tested use GNU Fortran 13, 14.2 and 16. CMakeLists.txt also contains flags for the Intel Fortran compiler.
  • CMake 3.18 or later. With PETSc 3.25, use CMake 4 (see Known problems).
  • An MPI library with Fortran and C bindings, such as OpenMPI.
  • pkg-config. CMake finds PETSc, SLEPc and NetCDF-Fortran through pkg-config, and ScaLAPACK through pkg-config or by the library name.
  • xz, to decompress the equilibrium files of the regression tests.
  • Optionally Python 3 with h5py and scipy, for the checks of the regression tests that read the HDF5 output.

PETSc must be built with complex scalars and double precision. The PETSc versions that are tested are 3.19, with SLEPc 3.19, and 3.25.3, with SLEPc 3.25.1. PETSc and SLEPc must have the same minor version.

Dependencies

PETSc, SLEPc, HDF5, NetCDF-Fortran and ScaLAPACK can come from the packages of a Linux distribution (Ubuntu packages), from Spack (Spack), or from a build from source, which is the usual route on a cluster (PETSc and SLEPc from source). PSPLINE and LIBSTELL are built by hand in all cases, with the scripts in the directory Libraries of the code (PSPLINE and LIBSTELL).

Ubuntu packages

On Ubuntu 24.04, which the continuous integration of PB3D uses, the packages are installed with 

sudo apt-get install gfortran g++ cmake pkg-config xz-utils \
    libopenmpi-dev openmpi-bin \
    libpetsc-complex3.19-dev libslepc-complex3.19-dev \
    libhdf5-openmpi-dev libnetcdff-dev \
    liblapack-dev libblas-dev libscalapack-openmpi-dev
export PETSC_DIR=/usr/lib/petscdir/petsc3.19/x86_64-linux-gnu-complex
export SLEPC_DIR=/usr/lib/slepcdir/slepc3.19/x86_64-linux-gnu-complex
export PKG_CONFIG_PATH=$PETSC_DIR/lib/pkgconfig:$SLEPC_DIR/lib/pkgconfig
export NETCDF_FORTRAN_DIR=/usr

The parallel HDF5 of these packages is selected at the configuration of PB3D with -DHDF5_ROOT=/usr/lib/x86_64-linux-gnu/hdf5/openmpi. The continuous integration solves the eigenvalue problem with these packages on one process only. Whether a PETSc has MUMPS can be checked in the file petscconf.h of PETSc, which defines PETSC_HAVE_MUMPS if it has: 

grep PETSC_HAVE_MUMPS $PETSC_DIR/include/petscconf.h

Spack

The file spack.yaml in the code describes a Spack environment with PETSc 3.25 (complex scalars), SLEPc 3.25, parallel HDF5 with Fortran bindings, NetCDF-Fortran, ScaLAPACK and pkg-config. It was tested with GCC 16 and OpenMPI 5 on macOS (Apple Silicon). On macOS, Apple Clang has no Fortran compiler, so GCC has to be installed first, for example with Homebrew (brew install gcc). The environment is created and built with 

git clone https://github.com/spack/spack.git $DEPS/spack
. $DEPS/spack/share/spack/setup-env.sh
spack compiler find
spack external find cmake openmpi gmake perl python
cd $PB3D_SRC
spack env create pb3d-env spack.yaml
spack env activate pb3d-env
spack concretize -f
spack install
export NETCDF_FORTRAN_DIR=$(spack location -i netcdf-fortran)

The command spack external find lets Spack use the MPI library and the tools that are already installed instead of building them. The first spack install takes a long time, because it builds PETSc and SLEPc with their dependencies. With the environment active, pkg-config and CMake find the libraries of the environment. The PETSc of spack.yaml has no MUMPS, so PB3D runs with it on one process only.

PETSc and SLEPc from source

A build from source is needed when no PETSc with complex scalars is available, which is often the case on clusters, or when PB3D has to run on more than one process and the available PETSc has no MUMPS. The compilers, MPI, BLAS/LAPACK, ScaLAPACK, parallel HDF5 and NetCDF-Fortran then come from the system, for example from its environment modules. The following recipe was tested with PETSc 3.25.3, which downloads and builds MUMPS, ParMETIS and METIS itself, and SLEPc 3.25.1. The options –with-blaslapack-lib and –with-scalapack-lib must point to the libraries of the system; the values below are examples. 

cd $DEPS
curl -L -O https://web.cels.anl.gov/projects/petsc/download/release-snapshots/petsc-3.25.3.tar.gz
tar xzf petsc-3.25.3.tar.gz
cd petsc-3.25.3
export PETSC_DIR=$PWD PETSC_ARCH=arch-complex-opt
./configure --prefix=$DEPS/petsc \
    --with-scalar-type=complex --with-precision=double --with-debugging=0 \
    --with-cc=mpicc --with-cxx=mpicxx --with-fc=mpif90 \
    --with-blaslapack-lib="-L/path/to/blas/lib -lopenblas" \
    --with-scalapack-lib="-L/path/to/scalapack/lib -lscalapack" \
    --download-mumps --download-parmetis --download-metis \
    --with-fortran-bindings=1 --with-shared-libraries=1 --with-x=0 \
    COPTFLAGS=-O2 CXXOPTFLAGS=-O2 FOPTFLAGS=-O2
make all
make install

cd $DEPS
curl -L -O https://slepc.upv.es/download/distrib/slepc-3.25.1.tar.gz
tar xzf slepc-3.25.1.tar.gz
cd slepc-3.25.1
export PETSC_DIR=$DEPS/petsc SLEPC_DIR=$PWD
unset PETSC_ARCH
./configure --prefix=$DEPS/slepc
make
make install

export PKG_CONFIG_PATH=$DEPS/petsc/lib/pkgconfig:$DEPS/slepc/lib/pkgconfig:$PKG_CONFIG_PATH

PETSc then uses MUMPS for the distributed LU factorization without any setting in PB3D. The build of PETSc with MUMPS takes about half an hour on 16 cores. The code contains the scripts that build PB3D in this way on one cluster, in the directory scripts/snellius; their paths and modules are those of that cluster.

PSPLINE

The script Libraries/build_pspline.sh builds PSPLINE with gfortran, without NetCDF, from a clone of github.com/ilonster/pspline. It first applies the patch Libraries/pspline-r8genxpkg-nx3.patch, which has to lie next to the script. The patch stops the routine r8genxpkg from writing 8 bytes past the end of its array for three unevenly spaced points; PB3D calls it with such points, and without the patch about every other run crashes on macOS. The script is copied into the clone and run there: 

git clone --depth 1 https://github.com/ilonster/pspline.git $DEPS/pspline
cp $PB3D_SRC/Libraries/build_pspline.sh $PB3D_SRC/Libraries/pspline-r8genxpkg-nx3.patch $DEPS/pspline/
$DEPS/pspline/build_pspline.sh
export PSPLINE_DIR=$DEPS/pspline/install

The library and the module files are then in $DEPS/pspline/install/lib and $DEPS/pspline/install/include.

LIBSTELL

PB3D uses only the module read_wout_mod of LIBSTELL. The script Libraries/build_libstell_min.sh compiles this module and the modules it depends on from a clone of STELLOPT into a small static library. It needs mpif90 and NetCDF-Fortran; NETCDF_FORTRAN_DIR is the installation directory of NetCDF-Fortran, which contains include/netcdf.inc. 

git clone --depth 1 https://github.com/PrincetonUniversity/STELLOPT.git $DEPS/stellopt
STELLOPT_SRC=$DEPS/stellopt NETCDF_FORTRAN_DIR=$NETCDF_FORTRAN_DIR \
    $PB3D_SRC/Libraries/build_libstell_min.sh $DEPS/libstell-min
export LIBSTELL_DIR=$DEPS/libstell-min

The last argument of the script is the installation directory. It should always be given, because the default of the script assumes that the code lies in $HOME/Code/PB3D. Both scripts put /opt/homebrew/bin at the front of PATH, so on macOS they use the compilers of Homebrew. A full LIBSTELL, built with the build system of STELLOPT, works as well. CMake looks under LIBSTELL_DIR (or STELLOPT_DIR) for the library libstell and for the module file vsvd0.mod or vmec_input.mod.

Compilation with CMake

When all dependencies are available, PB3D is configured and compiled in a separate build directory: 

cmake -S $PB3D_SRC -B $PB3D_SRC/build \
    -DCMAKE_BUILD_TYPE=Release \
    -DPSPLINE_DIR=$PSPLINE_DIR \
    -DLIBSTELL_DIR=$LIBSTELL_DIR
cmake --build $PB3D_SRC/build -j

With the Ubuntu packages, the configuration also needs -DHDF5_ROOT=/usr/lib/x86_64-linux-gnu/hdf5/openmpi. At the end of the configuration, CMake prints a summary of the dependencies it found. The executables PB3D and POST are created in the build directory. cmake –install $PB3D_SRC/build –prefix DIR copies them into DIR/bin.

A debug build, which has the debug code of PB3D and the runtime checks of the compiler, is made in a second build directory: 

cmake -S $PB3D_SRC -B $PB3D_SRC/build-debug \
    -DCMAKE_BUILD_TYPE=Debug -DPB3D_ENABLE_DEBUG=ON \
    -DPSPLINE_DIR=$PSPLINE_DIR -DLIBSTELL_DIR=$LIBSTELL_DIR
cmake --build $PB3D_SRC/build-debug -j

The following options and variables are passed to CMake with -D:

Table 1. CMake options and variables
name default explanation
CMAKE_BUILD_TYPE Release compiler flags: Release optimizes with -O3, Debug compiles with -O0 -g and the runtime checks of the compiler, RelWithDebInfo uses -O2 -g
PB3D_ENABLE_DEBUG OFF defines the preprocessor flag ldebug, which compiles the debug code of PB3D: the command-line options test, mem_info and invert_top_bottom_H (see Input variables), and additional checks and output; it is independent of CMAKE_BUILD_TYPE
PB3D_ENABLE_INFINIBAND OFF defines the preprocessor flag lIB, which switches off data sieving for reading and writing (the ROMIO hints romio_ds_read and romio_ds_write) when PB3D opens its HDF5 files through MPI-IO
PB3D_BUILD_EXECUTABLES ON with OFF, only the core library of PB3D that needs no external library is built, with its unit tests
BUILD_TESTING ON builds the test suite (see Tests)
PSPLINE_DIR none installation directory of PSPLINE; PSPLINE_ROOT and the environment variables PSPLINE_DIR and PSPLINE_ROOT work as well
LIBSTELL_DIR none installation directory of LIBSTELL; LIBSTELL_ROOT, STELLOPT_DIR and the environment variables of the same names work as well
HDF5_ROOT none standard CMake variable that selects the HDF5 installation; PB3D needs the parallel HDF5
PB3D_FIXTURE_DIR fixtures in the build directory directory with the equilibrium files of the regression tests; by default, CMake decompresses the files of tests/fixtures into it with xz
PB3D_TEST_MPI_REGRESSION OFF adds regression tests that run PB3D under mpirun -n 2 and -n 4 and require the eigenvalue to agree with the one-process run to \(10^{-6}\); they need PETSc with MUMPS
Python3_EXECUTABLE found by CMake Python of the regression checks that read the HDF5 output; without h5py, these checks are skipped

Tests

The tests are run with CTest from the build directory: 

ctest --test-dir $PB3D_SRC/build --output-on-failure

They are grouped in layers, which are selected by their labels, for example with ctest -L unit:

Table 2. Test layers
label needs contents
unit a Fortran compiler (and LAPACK for some suites) unit tests of the core library
smoke the executables PB3D and POST print their usage message
fullstack the executables and all dependencies tests of the modules against analytical and brute-force references, mainly of the vacuum; some also run under mpirun -n 2 and -n 4
regression the executables and the equilibrium files complete runs of PB3D on the equilibrium files of tests/fixtures, with the eigenvalues compared to recorded values; runs that check that PB3D refuses wrong inputs with a message; and regression_post_checks, which runs POST on the output of a run with three solutions

The tests that run under mpirun carry the label mpi as well, and ctest -LE mpi leaves them out. The unit tests can also be built without any of the external libraries: 

cmake -S $PB3D_SRC -B $PB3D_SRC/build-tests -DPB3D_BUILD_EXECUTABLES=OFF
cmake --build $PB3D_SRC/build-tests -j
ctest --test-dir $PB3D_SRC/build-tests --output-on-failure

CMake still looks for a C compiler in this case, because the project declares that language. The file Documentation/testing.md of the code describes every test and the recorded eigenvalues.

Known problems

  • With more than one MPI process, a PETSc without MUMPS stops the eigenvalue solver with the message "Could not locate a solver type for factorization type LU and matrix type mpibaij", which PB3D reports as error code 92 from get_solution(). The solver uses shift-invert, which needs an LU factorization of a distributed matrix, and the LU factorization of PETSc itself works on one process only.
  • With PETSc 3.25, CMake 3.31 does not finish the dependency scan of the Fortran header files of PETSc. The scan runs for a quarter of an hour and uses 13 GB of memory before the compilation starts. CMake 4 does not have this problem.
  • On macOS with OpenMPI 5 from Homebrew, mpirun itself can crash while it detects the hardware. PB3D then still runs on one process when the executable is called directly, without mpirun, and ctest -LE mpi skips the tests that use mpirun.
  • GNU Fortran 14.2 and 14.3 compile the bounds check of an array subscript that contains a function call with an array-constructor argument wrongly. CMake therefore removes -fcheck=bounds from the flags of the debug build for every GNU Fortran 14.
  • PB3D stores file names in strings of 120 characters, so the paths of the input and equilibrium files given on the command line must not be longer than that. A symbolic link with a short name helps.
  • A PSPLINE built without the patch of PSPLINE makes about every other run crash on macOS, with a SIGTRAP or a failure of H5Fcreate.

Legacy Makefile

The code also contains a hand-written Makefile, Makefile.legacy, which is kept for reference. Its paths have to be edited by hand, and neither the tests nor the continuous integration use it. CMake is the supported way to build PB3D.
