This page describes the various outputs that PB3D and POST can produce.

On the one hand, there are various text output files, which are discussed in section Output Files.

Furthermore, a multitude of plots can be produced. This is the topic of section Output Plots.

Output Files

Some of these files are opened in open_output(), but others are opened afterwards.

Log file

Both PB3D and POST produce a log file, in addition to what is produced on the screen.

These log files are called PB3D_out.txt and POST_out.txt and they contain the same information as the output on the screen, but without the special formatting provided by the foul library (see Introduction). When PB3D continues from an earlier run (rich_restart_lvl larger than 1), it appends to PB3D_out.txt instead of replacing it.

Shell commands file

Some output routines make use of use_execute_command_line() in order to execute shell commands. This can be, for example, the creation of a plot by calling GnuPlot, among other things.

However, this often does not work well by default (see 30 in Input variables). In PB3D and POST, therefore, by default, these commands are not executed, but written to the output files PB3D_shell_commands.sh and POST_shell_commands.sh. After PB3D or POST has finished, this file can be executed.

This behavior can be changed using the –do_execute_command_line flag (see Input variables).

HDF5 output file

PB3D writes variables to the HDF5 output file PB3D_out.h5 during execution, as shown in table 1. Note that there is a difference between the equilibrium styles because of the way how the equilibrium codes provide output:

  • VMEC (eq_style = 1) produces double Fourier series:
    • This can be evaluated at arbitrary angular points.
    • In PB3D, the equilibrium and perturbation variables are therefore already calculated on the field-aligned grid.
    • Parallel integration can then be done directly.
  • HELENA (eq_style = 2) produces 2-D tables for the poloidal cross-section.
    • This needs to be interpolated along the magnetic field lines before parallel integration.
    • The equilibrium and perturbation variables are calculated first in the HELENA grid.

A group name that ends in R[lvl] is written for every Richardson level [lvl]. For the grids, a Richardson level above 1 only holds the parallel points that are new at that level, and POST combines the levels (see reconstruct_pb3d_grid()). The level rich_restart_lvl is 1 unless PB3D continues from an earlier run.

grid_eq: equilibrium grid of grid_vars.grid_type grid_eq_R_[lvl], field-aligned, at every Richardson level grid_eq, the HELENA output grid, written once at the level rich_restart_lvl
grid_eq_B: field-aligned equilibrium grid not written: the equilibrium grid is field-aligned grid_eq_B_R_[lvl], at every Richardson level

The matrices \(\overline{\text{G}}\) and \(\overline{\text{H}}\) of the vacuum boundary-element method are not written; PB3D calculates them again when it continues from an earlier run (see print_output_vac()).

This data is used for Richardson restart (see variable rich_restart_lvl in Input variables) and for –jump_to_sol.

In the post-processing phase, POST reads this data as well.

POST, and PB3D when it continues from an earlier run, check the version of PB3D that wrote the file. If that version is older than the minimum version set by min_PB3D_version in num_vars, they stop with the message The output is from PB3D version [version]: need at least version [min_PB3D_version] (see reconstruct_pb3d_in()).

Eigenvalue summary file

In each Richardson extrapolation level, after the solution of the eigenvalue system of equations, PB3D writes the eigenvalues to the text file PB3D_out_EV_R_[lvl].txt, where [lvl] is the Richardson level. This is done in the procedure store_results():

  • The header says whether the eigenvalues are normalized. For VMEC it gives the normalization frequency in Hz, for HELENA it refers to the MISHKA normalization.
  • Every line holds the index of the eigenvalue, its real part, its imaginary part and the relative error that SLEPc gives for it.
  • An eigenvalue is marked by a # at the start of its line, followed by a warning line, in three cases. The first case is an unphysical complex eigenvalue: the absolute value of the ratio of its imaginary part to its real part is larger than 10 times the SLEPc tolerance tol_SLEPC of that Richardson level. The second case is an eigenvalue that lies within a relative distance of \(10^{-3}\) from the artificial eigenvalue EV_BC that the boundary conditions introduce. The third case is an eigenvalue larger than \(10^{40}\) in absolute value; all the following eigenvalues are then discarded as well.
  • The marked eigenvalues are removed from the solution, unless the option retain_all_sol is set (see Input file).

Energy reconstruction file

If energy reconstruction is performed by POST (see plot_E_rec in Input variables), the individual terms that make up the perturbed potential energy as well as the kinetic energy of the perturbation are calculated and plotted. (3) Furthermore, the integrals of these quantities over the whole volume are written to the text file POST_out_EN_R[lvl].txt, where [lvl] is the Richardson level of the PB3D output that POST uses. For every eigenvalue, the file holds a line with the index of the eigenvalue, followed by three pairs of lines; the first line of a pair holds the real parts and the second line the imaginary parts of:

  • the eigenvalue, the ratio \(E_\text{pot}/E_\text{kin}\), \(E_\text{pot}\) and \(E_\text{kin}\),
  • the normal and geodesic kinetic terms,
  • the normal and geodesic line bending terms, the normal and geodesic ballooning terms, the normal and geodesic kink terms, and the vacuum term.

In table 2, an overview is given of the different terms. Here, \(\rho\) is the density, \(\sigma = \frac{\vec{B}\cdot\vec{J}}{B^2}\) is the parallel current and \(\kappa = \frac{\vec{B}}{B} \cdot \nabla \frac{\vec{B}}{B}\) is the magnetic curvature. See calc_e().

Table 2. energy reconstruction
potential energy \(E_\text{pot}\) kinetic energy \(E_\text{kin}\)
  • normal line bending term \(\frac{1}{\left|\nabla\psi\right|^2 }\left(\frac{\nabla \psi}{\left|\nabla \psi\right|^2}\cdot \vec{Q}\right)^2\)
  • geodesic line bending term \(\mathcal{J}^2\frac{\left|\nabla \psi\right|^2}{B^2} \left( \frac{\nabla \psi \times \vec{B}}{B^2}\cdot \vec{Q} \right)^2\)
  • normal ballooning term \(-2 p' \left(\nabla \psi \cdot \vec{\xi}\right)^2 \left(\nabla \psi \cdot \vec{\kappa}\right)\)
  • geodesic ballooning term \(-2 p' \left( \nabla \psi \cdot \vec{\xi} \right) \left( \frac{\nabla \psi \times \vec{B}}{\left|\nabla \psi \right|^2} \cdot \vec{\xi}\right)^* \left(\frac{\nabla \psi \times \vec{B}}{\left|\nabla \psi \right|^2} \cdot \vec{\kappa}\right)\)
  • normal kink term \(-2 \sigma \left(\nabla \psi \cdot \vec{\xi}\right)^* \left(\frac{\nabla \psi \times \vec{B}}{B^2}\cdot \vec{Q} \right)\)
  • geodesic kink term \( 2 \sigma \left(\frac{\nabla \psi \times \vec{B}}{B^2} \cdot \vec{\xi}\right)^* \left(\nabla \psi\cdot \vec{Q} \right)\)
  • vacuum term \(\vec{X}_\text{e}^\dagger \overline{\text{R}} \vec{X}_\text{e}\), where \(\vec{X}_\text{e}\) holds the Fourier coefficients of the eigenvector at the last point of the solution grid and \(\overline{\text{R}}\) is the vacuum response matrix in the vac group of the HDF5 output; this term is zero for a fixed boundary (BC_style(2) = 1)
  • normal kinetic term \(\frac{1}{\left|\nabla\psi\right|^2 }\left(\frac{\nabla \psi}{\left|\nabla \psi\right|^2}\cdot \vec{\xi}\right)^2\)
  • geodesic kinetic term \(\mathcal{J}^2\frac{\left|\nabla \psi\right|^2}{B^2} \left( \frac{\nabla \psi \times \vec{B}}{B^2}\cdot \vec{\xi} \right)^2\); this term is zero for K_style = 2

Memory usage file

The memory usage of PB3D and POST can be monitored using the optional input argument –mem_info (see Command-line inputs). The memory usage is then written to the files PB3D_mem_usage.dat and POST_mem_usage.dat, with for every entry the MPI rank, a counter, the time, the memory usage and the maximum total and perturbation memory.

This is a rather crude implementation and more advanced profiling methods should be used, such as Scalasca on top of Score-P.

Note
Debug version only

Vacuum check output

If the PB3D input check_vac is set for a free boundary, calc_vac_res() tests the assembled vacuum operators with potentials whose boundary values are known exactly, before it solves for the vacuum response (see check_vac_exact()). The results are written to the log file, on lines that start with CHECKVAC. The values per boundary point are written to the files check_vac_*.dat in the run directory, with the index of the point, its index along the field line, the index of the field line, its position and the value. The values of the exterior potential away from the boundary are written to check_vac_exterior.dat.

Output Plots

A multitude of plots can be produced by PB3D and POST.

POST can produce all the plots that PB3D can, and some more.

The plots themselves fall in two categories:

  • Plots using an external program.
    • Produced by output_ops.print_ex_2d() or output_ops.print_ex_3d() combined with draw_ex().
    • A list of external programs is given in draw_ex().
    • The data files are written in Data/, the scripts in Scripts/ and the resulting plots in Plots/.
    • These plots require a shell command to be run, which is disabled by default and the commands are stored in a Shell commands file.
    • The produced plots can be 2-D or 3-D, and they can be interactive or not, depending on the ex_plot_style (see Input variables).
  • Data files that can be used to produce plots with visualization software:
    • The software used here was VisIt, based on personal preference, but ParaView or other VTK-based solutions should work equally well.
    • Every plot creates two output files in Data/: one heavy-data HDF5 file and one XDMF file that contains specifics about the HDF5 file.
    • This is necessary, as HDF5 itself is too general a format for general visualization tools to interpret easily.
    • The XDMF file that accompanies each HDF5 file basically contains information about the saved variables, such as whether they are vectors or scalars, and on which grid type they are defined.
    • This is the file that should be opened by the visualization software.
    • The dimensions of these plots can be 2-D or 3-D, depending on eq_style. See 19 and 20 in Input variables.

An overview of possible plots is now given in table 3. The name of the respective input parameter is provided as well. See Input variables.
