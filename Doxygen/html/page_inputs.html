This page describes the input variables of PB3D and POST.

Most inputs are read from the user input file, which holds the Fortran namelist inputdata_PB3D for PB3D or inputdata_POST for POST. Every variable that is not set in the file keeps its default value. A name in the file that is not part of the namelist stops the program with the error "Cannot read user-provided file". The other inputs are options on the command line. PB3D and POST are called as 

PB3D USER_INPUT EQUILIBRIUM_INPUT [OPTIONS]
POST USER_INPUT PB3D_OUTPUT [OPTIONS]

where the options take the form –[option_name], sometimes followed by values. The user input file has to exist, also when it sets no variable: there is no default input file. If the file cannot be opened, the program stops with the error "Cannot open input file" (see runtime errors).

See also
See init_files() and open_input().

For both PB3D and POST, both types of input are discussed.

Some general remarks:

  • There is some fault detection built into the routines. These distinguish between minor faults, which trigger a warning but do not stop execution, and major faults, which trigger an error that stops execution.
    See also
    See writo().
  • The data type real refers to double precision real, defined by num_vars.dp. For integers, standard precision is used. A type such as int(2) is an array of two values, given in the input file as two numbers separated by a space.
  • Angles are given in units of \(\pi\), marked \(\left[\pi\right]\).
  • PB3D takes a file with the extension .nc as a VMEC file, which gives eq_style = 1, and a file that starts with an integer as a HELENA file, which gives eq_style = 2. Several defaults depend on eq_style. POST reads eq_style from the PB3D output.
  • PB3D limits the tolerances tol_rich, tol_zero and tol_SLEPC to the range from min_tol \(= 10^{-12}\) to max_tol \(= 10^{-3}\), which are hard-coded in read_input_opts().
  • If eq_style = 2 (i.e. HELENA), the total maximum memory available must be enough to perform the first Richardson level in a single equilibrium job (see General code structure).
  • PB3D computes the vacuum response only for a free boundary, BC_style(2) = 2. No input chooses the vacuum style. PB3D takes the field-line 3-D style for a VMEC equilibrium and the axisymmetric style for a HELENA equilibrium (see 37).

  37. PB3D computes the vacuum response, in calc_vac_res(), only for a free boundary, BC_style(2) = 2; with BC_style(2) = 1, it skips the vacuum. The vacuum style follows from the equilibrium. For a VMEC equilibrium, PB3D uses the field-line 3-D style (style 1): a boundary-element method on the points of the field lines on the plasma boundary. It needs several field lines, so a free-boundary VMEC run with alpha_style = 1 stops with an error; PB3D computes the vacuum at every Richardson level. For a HELENA equilibrium, PB3D uses the axisymmetric style (style 2), with toroidal functions on the boundary of the poloidal cross-section, and it computes the vacuum once, at the first Richardson level of the run (rich_restart_lvl). PB3D solves the boundary-element system with the LU factorization of ScaLAPACK.
  38. The check runs inside calc_vac_res(), so only when PB3D computes the vacuum (see 37). check_vac_exact() tests the boundary-element matrices on the plasma boundary of the equilibrium with potentials that are harmonic inside the boundary (the constant, the Cartesian coordinates \(x\), \(y\), \(z\), and \(x^2 - y^2\)) and with potentials that are harmonic outside it and decay (a point source on the magnetic axis and a ring of point sources along the axis). It prints the residuals of the Green identities, the errors of the exterior solution and the differences between the assembled diagonals and the alternative ones on lines of the log that start with CHECKVAC. It also writes the values at the boundary points to files check_vac_*.dat in the run directory. The check is compiled only in the debug version (CMake option PB3D_ENABLE_DEBUG, see Compilation with CMake); a build without it warns that it ignores check_vac and runs without the check.
  39. For the field-line style, the indirect diagonals follow from the row sums for the constant and the linear interior harmonics; for the axisymmetric style, they follow from the identities of two known potentials, the two solutions of the Legendre equation of a ring at the centroid of the boundary, solved exactly at every point (diag_indirect()). The direct diagonals use the corner term and the integral of the kernel over the cell of the node (calc_diag_direct() for the field-line style). Style 1 is the more accurate of the two, and PB3D prints a warning that style 2 is a diagnostic, not meant for production runs, when it is used with a free boundary. With check_vac, PB3D reports the difference between the assembled diagonal and the other one at every point. A value other than 1 or 2 stops PB3D with an error message.
  40. POST plots the vacuum potential only for a free boundary; for a fixed boundary it switches plot_vac_pot off. It evaluates the potential in the planes of constant \(\zeta\) of the plasma plots (n_zeta_plot planes from min_zeta_plot to max_zeta_plot), on a grid of n_vac_plot(1) by n_vac_plot(2) points in \(R\) and \(Z\). If max_Rvac_plot is not larger than min_Rvac_plot, which is the case for the defaults, the range in \(R\) is the range of the boundary points widened on both sides by half the larger of the widths of the boundary in \(R\) and in \(Z\), and it starts at no less than 0.1 times the smallest \(R\) of the boundary; the same rule with min_Zvac_plot and max_Zvac_plot sets the range in \(Z\). A range given by the user must have a positive min_Rvac_plot. The limits are in metres. For a HELENA equilibrium without a user-given R_0, PB3D sets R_0 = 1, and the limits are then in units of the length scale of the HELENA equilibrium. See vac_pot_plot() for the output.

For the field-line 3-D vacuum, the convergence studies in README.md of the code recommend at least 128 field lines and about 36 parallel points per poloidal wavelength of the perturbation.
