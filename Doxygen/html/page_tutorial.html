This page contains a hands-on tutorial to get you used to running PB3D to calculate 3-D ideal linear high-n MHD stability, and POST to post-process the results.

Be sure to check out the Installation instruction first.

If at any point a routine is not clear, don't hesitate to consult the Procedures and Variables page.

Getting the Equilibrium

PB3D calculates stability of an equilibrium magnetic toroidal configuration. It is written in a modular way to isolate this main task from the actual code that was used to obtain the equilibrium configuration, and the format that this code may use. Currently, two formats are possible:

  • 3-D VMEC [7].
  • Axisymmetric HELENA [9].

VMEC is a general 3-D code built on an interesting idea: The poloidal coordinate \(\theta\) is deformed in such as a way to make the Fourier basis that is used to describe the cylindrical coordinates \(R(s,\theta,\varphi)\) and \(Z(s,\theta,\varphi)\) as narrow as possible, where \(s\) is the flux label ( \(s=\Psi_\text{tor}/\Psi_{\text{tor,edge}}\), the normalized toroidal flux) and \(\varphi\) is the regular cylindrical angle (1). This is done by introducing a deformation factor \(\lambda(s,\theta,\varphi)\) defined so that the straight-field line coordinate \(\theta_\text{F}\) is given by \(\theta_\text{F} = \theta + \lambda \).

The fact that \(R\), \(Z\) and \(\lambda\) are given as a double Fourier series in \(\theta\) and \(\zeta\) ensures that the angular derivatives can be done analytically. This property is used in PB3D. Apart from that, the flux functions that describe the profiles on the flux surfaces, the rotational transform \(\iota(s)\) and pressure \(p(s)\), are also returned.

For HELENA, the situation is different, as this code considers axisymmetric equilibria only. Its output consists, aside from flux functions safety factor \(q(\psi)\), pressure \(p(\psi)\) and toroidal covariant magnetic field \(F(\psi)\), where \(\psi=\Psi_\text{pol}/\Psi_{\text{pol,edge}}\) is the normalized poloidal flux, of a 2-D table for the upper metric factors \(h^{\psi\psi}\) and \(h^{\psi\theta}\) and the lower metric factor \(g_{\zeta\zeta}\). HELENA uses the same angular coordinates \(\theta\) and \(\zeta = -\varphi\) as PB3D (see 1).

Note
The modular nature of PB3D enables easy integration of other equilibrium codes, if necessary.

To get the appropriate equilibrium code results into PB3D, it suffices to place the output files in the same directory in which PB3D is run:

  • for HELENA, it is a text file, corresponding to the mapping file (fort.12),
  • for VMEC, it is the so-called wout file,

and to specify their names as the second input argument, the first one being the file with user inputs (see Setting Up the Input File).

Note
For VMEC, the wout file has to be in NetCDF format, and its name has to end in .nc, because PB3D recognizes a VMEC file by this extension (see open_input()). The .txt format of VMEC is not supported.

In any case, if you forget how to run the PB3D (or POST) programs, you can always just type

./PB3D --help

or even just

./PB3D

Patching HELENA

PB3D needs a HELENA that is changed in three places from the usual version. All three are in the subroutine mapping, which writes the mapping file fort.12.

  1. HELENA writes IAS after JS0 and B0 after RAXIS. Some versions do not write these by default. If yours is one of them, change
    write(nmap,8) JS0
    to
    write(nmap,8) JS0, IAS
    and
    write(nmap,8) RAXIS
    to
    write(nmap,8) RAXIS, B0
    Without them, PB3D stops with the error "Failed to read HELENA output file".
  2. HELENA writes the mapping file with 16 significant digits. HELENA's own formats write 8. Change the formats of the mapping output from E16.8 to E24.16:
    6 FORMAT(4E24.16)
    7 FORMAT(2E24.16)
    9 FORMAT(E24.16)
    (format 11, of the profile file fort.21, may change the same way; PB3D does not read that file). PB3D reads the file in free format, so it reads both versions without any change.
  3. HELENA is compiled in double precision, for example with gfortran -fdefault-real-8 -fdefault-double-8. In single precision, 16 written digits do not help.

Then recompile and re-run HELENA.

The 16 digits are not a claim about the accuracy of the equilibrium. HELENA's own discretisation error changes smoothly from one poloidal point to the next, but rounding to 8 digits adds an independent error of up to \(5\times10^{-8}\) at each point. PB3D takes up to three derivatives in the poloidal angle \(\chi\), which multiply such an error by about \(1/h^3\), with \(h\) the spacing of the poloidal points. With 8 digits, the eigenvalue can be off by per cents at low \(n\) on fine mappings: with a free boundary at \(n = 5\) and 2049 poloidal points, by 2 % for a circular \(\epsilon = 0.33\) case and by 50 % for a pedestal case (PB3D issue 65). With 16 digits, the same cases converge smoothly in the number of poloidal points. Most of the error comes from the poloidal grid itself: HELENA sets it exactly to \(\chi_j = \pi (j-1)/(N_\chi-1)\) (or \(2\pi (j-1)/N_\chi\) without up-down symmetry), and 8 digits round it.

Note
PB3D checks this when it reads the file (see read_hel() and chi_h_rounding()). If the poloidal grid in the file differs from HELENA's exact grid by between \(10^{-12}\) and \(10^{-6}\), PB3D warns that the mapping file has too few digits and refers to this section. The run continues, because the error is small at higher \(n\) and on coarse mappings (0.1 % or less at \(n \geq 10\) with 1025 poloidal points), but the eigenvalue should not be trusted at low \(n\) on fine mappings.

Checking the equilibrium (optional)

It is always important that the equilibrium has been properly calculated, well-converged, etc.

It is possible to use PB3D to check this. This will be quickly described in this optional section.

The checks described below are only possible with the code compiled in the debug version, which is the CMake option -DPB3D_ENABLE_DEBUG=ON (see Installation). Using the debug version, the tests can be triggered using the --test option when running PB3D (or POST), and using the interactive user interface.

They generally output HDF5 files that can be read with ParaView or VisIt to check the difference between two plots. After having a look in the code (search for ltest), this should be self-explanatory.

Note
Most of the checks are only useful for developers. However, the tests on B_F and on the pressure balance consistency are vital.
Table 1. the most important tests
tests purpose
calculation of g_V Check whether equilibrium metric coefficients calculated for VMEC equilibria through application of transformation matrices match with a direct implementation of the VMEC metric coefficients. Note that the reason why the transformation matrices are used, is that derivatives can be easily calculated as well, with high precision.
calculation of jac_V Similar to the test on the calculation of g_V, but this time for the Jacobian of VMEC coordinates.
consistency of HELENA metric factors Check whether the metric factors returned by HELENA are consistent with the ones calculated from the flux quantities, \(R\) and \(Z\). Basically, this is a measure for the accuracy with which the pressure balance is satisfied.
harmonic content of HELENA output Analyze harmonic content of HELENA variables.
calculation of D1 D2 h_H Check whether the cross-derivatives are correctly and accurately calculated.
calculation of T_EF Check is \(\mathcal{T}_\text{E}^\text{F}\) complies with the (unpublished) theory.
calculation of jac_F Similar to the test on the calculation of jac_V, but this time for the Jacobian of Flux coordinates.
calculation of B_F Similar to the test on the calculation of jac_F, but this time for the covariant components and magnitude of the magnetic field in Flux coordinates.
consistency of pressure balance Check how well the pressure balance is satisfied. This is a very crucial requirement for the correct calculation of stability: If the pressure balance is not satisfied up to high precision, there is not much for PB3D to do.
calculation of DU Check how well the poloidal derivative of the geodesical component of the minimizing perturbation, \(U\), is calculated by comparing it to the numerical derivative.

For the specific case of VMEC equilibria, finally, there is the additional --plot_VMEC_modes option that produces outputs of the harmonics of the different quantities: \(R\), \(Z\), \(\lambda\), \(\mathcal{J}\) and \(\vec{B}\).

It is very important that these are well-converged, as the internal consistency depends strongly on this. Therefore, if this is not the case, be prepared to receive unaccurate stability results.

Setting Up the Input File

Now that we have the equilibrium files, it is time to have a look at the input file.

1&inputdata_PB3D
2 min_n_par_X = 100
3 min_par_X = 0.0
4 max_par_X = 2.0
5 alpha_style = 2
6 n_alpha = 64
7 min_r_sol = 0.3
8 max_r_sol = 1.0
9 n_r_sol = 400
10 prim_X = 10
11 n_mod_X = 20
12 BC_style = 1 2
13 U_style = 3
14 max_tot_mem = 6000
15 max_it_rich = 1
16 use_normalization = .true.
17/
18//! [some extra options for PB3D]
19 rich_restart_lvl = 1
20 tol_rich = 1.0E-4
21 tol_SLEPC = 1.0E-8 1.0E-8
22//! [some extra options for PB3D]

Have a look:

  • min_n_par_X is the number of points in the parallel grid of every field line at the first Richardson level.
  • These points range from min_par_X to max_par_X, in units of \(\pi\).
  • How the field lines are chosen depends on alpha_style. This file sets alpha_style = 2, which is also the default for VMEC: PB3D uses n_alpha field lines, here 64, with equally spaced labels, and follows each of them over one poloidal turn. PB3D sets min_par_X and max_par_X to 0 and 2 if their difference is not 2 (see Input variables); in this file, they are already 0 and 2.
  • With alpha_style = 1, the default for HELENA, PB3D follows the single field line with label alpha, and the parallel range from min_par_X to max_par_X can span several poloidal turns. For 3-D equilibria, the number of field lines n_alpha (alpha_style = 2) or the parallel range (alpha_style = 1), together with min_n_par_X, has to be increased until convergence is reached [14].
  • n_r_sol is the number of points in the solution grid, that ranges from min_r_sol to max_r_sol in the PB3D normal coordinate (see num_vars.use_pol_flux_f).
  • n_mod_X is the number of Fourier harmonics that are kept, with prim_X the primary mode number. With the poloidal flux as normal coordinate (the default), prim_X is the toroidal mode number \(n\) and the harmonics are poloidal mode numbers \(m\).
  • BC_style(1:2) indicates the style with which the boundary conditions are implemented deep in the plasma and on the plasma edge.
  • max_tot_mem is a memory limit in MB: PB3D divides its work into jobs so that its own estimate of the memory it needs stays below this limit. The estimate is larger than the memory the run really uses; section What to expect gives the numbers for this example. The estimate includes the memory that every process holds before the work starts (MPI, the libraries and the input), about 0.1 GB on macOS and 0.3 GB on Linux per process. When the limit is too low for the parts of the calculation that cannot be divided, PB3D stops at the start and gives the number of MB it needs.
  • max_it_rich is the number of Richardson levels (see the extra options below); with 1, PB3D does not extrapolate.
  • use_normalization indicates whether normalization is used (recommended), but it is useful to turn this off for debugging.
Note
In this file, BC_style = 1 2 makes the plasma edge a free boundary: PB3D calculates the response of the vacuum outside the plasma and adds its energy to the perturbed potential energy (see General code structure and Vacuum response). BC_style(2) = 2 is also the default. With BC_style = 1 1, the displacement is zero at the plasma edge, as if a conducting wall lay on the plasma surface, which makes it a fixed boundary. The inner end, deep in the plasma, only accepts BC_style(1) = 1. For VMEC, a free boundary needs alpha_style = 2 with more than one field line, as PB3D then uses a 3-D boundary-element method on the points of the field lines on the plasma boundary; PB3D stops with an error for alpha_style = 1. The number of field lines decides how well this method resolves the toroidal variation of the vacuum potential, \(e^{-in\zeta}\): there must be clearly more than \(2n+1\) of them. Section What to expect shows how accurate 64 field lines with 100 points each are for this example.

There are also some extra options listed (but not loaded in PB3D as they come after the end of the inputdata_PB3D block of the Fortran namelist) below:

19 rich_restart_lvl = 1
20 tol_rich = 1.0E-4
21 tol_SLEPC = 1.0E-8 1.0E-8

They include:

  • rich_restart_lvl is used to restart a simulation at a certain Richardson level. The Richardson level 1 refers to the first simulation, with the number of parallel points used in the calculation of line integrals along the magnetic field set by min_n_par_X (see inputs_PB3D_file_tab). For every subsequent Richardson level, this number \(n\) becomes \(2n-1\), so that the grid spacing is halved. The results from these different levels are extrapolated to a theoretically infinitely fine grid. These operations are done in module rich_ops.
  • tol_rich is the tolerance at which Richardson extrapolation is considered to have converged.
  • tol_SLEPC is an array of tolerances used for the SLEPc eigenvalue solutions of the different Richardson levels.

There are many, many more input parameters. A short description of these can be found in Input variables.

Running PB3D

This tutorial provides a VMEC equilibrium file to experiment with: the cbm18 equilibrium of the benchmark for edge-localized modes of Ferraro et al. [4], a nearly circular tokamak with a steep pressure pedestal at the edge, which is unstable to peeling-ballooning modes. The plasma ends at the foot of the pedestal, where the pressure gradient and the current density fall to zero, and outside it is vacuum. The file was made from the HELENA equilibrium of this plasma, with PB3D's option –export_HEL and VMEC++ on 639 flux surfaces; its safety factor agrees with that of HELENA to five digits. Lengths and fields are in SI units. Figure 1 shows the flux surfaces and the profiles of the pressure and the safety factor: the pressure falls from 25 kPa at \(\psi = 0.75\) to 0.2 kPa at \(\psi = 0.95\), where \(\psi\) is the normalized poloidal flux. Some properties are given in table 2.

major radius \(R_0\) and minor radius \(a\) (centre and half width of the boundary in the midplane), aspect ratio \(R_0/a\) \(3.49\,\text{m}\), \(1.20\,\text{m}\), \(2.9\)

Put this equilibrium file, as well as the input file in a separate run directory; let's call it cbm18.

In order to produce outputs, PB3D needs three sub-directories in the run directory, called Data/, Scripts/ and Plots/.

  • In Data/, the data files for the external plots are stored, as well as the HDF5 plots (.h5 and .xmf files) that can be read later in visualization software such as VisIt or ParaView.
  • In Scripts/, scripts are generated that use the data files from Data/.
  • In Plots/, the resulting external plots are located. In Output Plots, this is explained in more detail.

If these directories are not present, you will receive an error message, so go ahead and create them.

We can now run the code using mpirun. For example, with

mpirun -np 4 ./PB3D PB3D.input wout.nc

4 processes are used. With more than one process, the eigenvalue solver needs PETSc with a parallel direct solver such as MUMPS (see Frequently Asked Questions); a single process can also be used, by running ./PB3D PB3D.input wout.nc without mpirun. You can find the VMEC file here. The HELENA input file of the same plasma is here; with a HELENA patched as described in Patching HELENA, it gives the mapping file that PB3D reads instead of wout.nc.

Note
On macOS, run PB3D and POST with MallocLargeCache=0 in the environment, for example
MallocLargeCache=0 ./PB3D PB3D.input wout.nc
Without it, macOS keeps the memory that PB3D has freed, and PB3D can take about twice max_tot_mem; PB3D warns about this at the start. PB3D cannot set this variable itself, as it has to be set when the program starts.

There are optional run-time options that can be triggered, such as –jump_to_sol, which can be used to easily change solution preferences, such as discretization order, etc. For an overview, see Command-line inputs; they are not treated here.

You will see formatted output on the screen, with indentation according to the depth of a routine in the program. The same output is also written to the output file PB3D_out.txt, unformatted but still indented (see Log file).

The resulting eigenvalues can also be read in a separate output file, PB3D_out_EV_R_1.txt for the first Richardson level (see Eigenvalue summary file). The other results are written to the HDF5 file PB3D_out.h5, which POST reads.

Take a look at these output files and shuffle a bit with the input parameters if you want. For example, change n_mod_X to another value in order to get a different number of Fourier harmonics, or n_r_sol to change the number of normal grid points in the solution. The solution should not change a lot if you have enough harmonics and normal grid points.

Note
For VMEC, the magnetic axis is a bit problematic. It is necessary, therefore, to choose min_r_sol to be slightly larger than 0; 0.01 for example.

What to expect

On one core of a laptop (Apple M3 Pro, with MallocLargeCache=0), this run takes about 2.5 minutes, and its memory use peaks at 3.5 GB, below the limit max_tot_mem of 6000 MB. Most of the time goes into the plasma quantities on the 64 field lines, which PB3D divides into 34 equilibrium jobs; the vacuum takes 15 s. This input file needs a max_tot_mem of at least 4.9 GB on this laptop and about 5.2 GB on Linux: the solution driver holds the vacuum matrices and the integrated perturbation quantities at the same time, which cannot be divided into jobs, and the process holds memory of its own. With a lower limit, PB3D stops at the start and gives the number it needs.

PB3D gives the eigenvalues \(\lambda = \omega^2/\omega_A^2\), normalized to the square of the Alfvén frequency \(\omega_A\) that the header of PB3D_out_EV_R_1.txt gives. For this input file, the first eigenvalue should be close to \(\lambda = -0.0499\). A negative eigenvalue belongs to an unstable mode, with the growth rate \(\gamma = \omega_A\sqrt{-\lambda}\), here \(0.22\,\omega_A\).

Figure 2 shows the eigenvector: the amplitudes of the poloidal Fourier harmonics \(X_m\) of the normal displacement \(X = \vec{\xi}\cdot\nabla\psi\). Each harmonic peaks close to the flux surface on which it is resonant, where \(n|q| = m\); the upper axis of the figure gives \(n|q|\). The largest harmonics, \(m = 18\) to \(23\), lie where the pressure falls most steeply. At the plasma boundary, where \(n|q| = 30.4\), the harmonic \(m = 31\), which would be resonant just outside the plasma, still has 0.27 of the largest amplitude, so that the mode moves the boundary.

Figure 2: amplitudes of the poloidal Fourier harmonics of the normal displacement of the first eigenvector, for n = 10, divided by the largest value. The upper axis gives n|q|; each harmonic m peaks close to where n|q| = m.

Figure 3 shows the same eigenvector in the poloidal plane \(\zeta = 0\), and the potential of the perturbed magnetic field in the vacuum outside the plasma. The displacement is largest on the outboard side, where the curvature of the field lines makes the pressure gradient destabilizing: the mode balloons. Outside the plasma, the vacuum potential falls off over a distance comparable to the distance between its maxima along the boundary. Figure 4 shows the displacement on the whole plasma boundary: its maxima and minima follow the field lines, with 10 periods around the torus, and it is largest on the outboard side. POST computes both figures (see Post-processing With POST); they were plotted with matplotlib from the HDF5 files that POST writes in Data/.

Figure 3: real part of the first eigenvector in the poloidal plane at zeta = 0. Left: the normal displacement X inside the plasma; the solution range starts at a normalized poloidal flux of 0.3. Right: the vacuum potential outside the plasma. Both in arbitrary units.
Figure 4: real part of the normal displacement X of the first eigenvector on the plasma boundary, over the whole torus (red positive, blue negative).

The times varied by about 15 % between repeated runs of the same input file, and more while other programs ran on the laptop. The table shows the following.

  • With 100 points on each field line, the points along the lines limit the accuracy of the vacuum. 200 points per line move the eigenvalue by 0.8 %, to within 0.1 % of the HELENA value, while 128 field lines instead of 64 move it by only 0.05 %.
  • With 30 Fourier harmonics instead of 20, the free-boundary eigenvalue on the HELENA mapping is 0.2 % more negative; the fixed-boundary eigenvalue on the HELENA mapping changes by less than \(10^{-4}\) of its value.
  • With the vacuum, the eigenvalue is 24 % more negative than with a conducting wall on the plasma surface, so the growth rate is 11 % larger.
  • min_r_sol = 0.3 lies far enough inward. On the HELENA mapping, with the same spacing of the radial points, the free-boundary eigenvalue changes by \(10^{-5}\) of its value when the solution range starts at 0.1 instead. When it starts at 0.5, the range cuts off the inner part of the eigenfunction, and the eigenvalue is 0.2 % less negative.
  • The radial grid is fine enough: with 1120 points instead of 400, the HELENA eigenvalue with a free boundary changes by 0.04 %.

Post-processing With POST

POST provides a way to visualize the results from PB3D. Many options are possible, and they can be activated using plot_ flags (see Input file).

An example is given in POST.input

1&INPUTDATA_POST
2 plot_resonance = .true.
3 plot_magn_grid = .true.
4 plot_flux_q = .true.
5 plot_sol_xi = .true.
6 plot_sol_Q = .true.
7 plot_E_rec = .true.
8 plot_B = .true.
9 plot_J = .true.
10 plot_kappa = .true.
11 min_r_plot = 0.3
12 max_r_plot = 1.0
13 n_theta_plot = 101
14 min_theta_plot = 0.00
15 max_theta_plot = 2.00
16 n_zeta_plot = 1
17 min_zeta_plot = 0.00
18 max_zeta_plot = 0.00
19 POST_style = 1
20 plot_grid_style = 0
21 pert_mult_factor_POST = 0.0000
22 max_tot_mem = 8000
23/
24//! [some extra options for POST]
25 ex_plot_style = 2
26 PB3D_rich_lvl = 1
27//! [some extra options for POST]

It can be seen that apart from the plot_ flags, there are also

  • min_r_plot and max_r_plot, which are the direct equivalent of min_r_sol and max_r_sol in PB3D.
  • min_theta_plot, max_theta_plot and n_theta_plot which indicate the range of the poloidal variable that is plot, as well as the number of points. There is an equivalent for the toroidal variable.
  • POST_style that allows the user to change between different styles, such as whether the output grid is chosen to fill the torus in a regular way, for example, or whether it follows the PB3D equilibrium grid.
  • plot_grid_style, subsequently, can be used to change the way in which these grids are produced. For example, they could be changed to slab plots or plots with a straightened toroidal angle.
  • pert_mult_factor_POST can be used to deform the output grids by the perturbation itself.

Also here, there are also some extra options listed below:

25 ex_plot_style = 2
26 PB3D_rich_lvl = 1

They include:

  • ex_plot_style to indicate which program is to be used for external plotting. Changing it to 2 would engage Bokeh and Mayavi.
  • PB3D_rich_lvl can be optionally employed to specify explicitly which Richardson level to use for the post-processing.

All of these options are explained in Input file. Again, there are also run-time options that can be found in Command-line inputs.

Now, run the POST program, for example using 4 MPI processes:

mpirun -np 4 ./POST POST.input PB3D_out.h5

For this example, POST takes about half a minute on one core.

An interesting output is the energy reconstruction, which is activated with plot_E_rec. This calculation reinserts the eigenvector into the terms of the perturbed potential energy and of the kinetic energy, in order to check whether the Rayleigh quotient still holds, and to see which terms are dominant and which ones are less important. The integrated terms are also stored in a separate file, POST_out_EN_R[lvl].txt for Richardson level [lvl] (see Energy reconstruction file).

Figure 5 shows these terms for this example, divided by the kinetic energy, so that they add up to the eigenvalue: their sum, \(-0.04984\), differs from the eigenvalue \(-0.04987\) by \(7\times10^{-4}\) of its value. The normal ballooning term, which holds the pressure gradient and the normal curvature of the field lines, drives the mode most, and the line bending terms stabilize it. The figure also shows the terms of the fixed-boundary run (BC_style = 1 1). The vacuum term itself is small and positive, \(+0.005\). The free boundary makes the mode more unstable because the eigenvector changes: with the free boundary, the normal ballooning term is more negative by 0.025 and the normal kink term, which holds the parallel current, by 0.012, while the line bending terms grow by 0.027.

Figure 5: terms of the potential energy of the first eigenvector, divided by its kinetic energy, for the free boundary of this tutorial and for a fixed boundary (POST, plot_E_rec).

Because this example has a free boundary, POST also plots the vacuum potential of the eigenmode outside the plasma (plot_vac_pot, which is set by default), in the files Data/1_vac_pot_RE.xmf and Data/1_vac_pot_IM.xmf for its real and imaginary parts; Data/vac_in_plasma.xmf marks the points of the plot that lie inside the plasma. After a fixed-boundary run, POST switches this plot off.

If –do_execute_command_line was not explicitly used, the actual external plot programs are not used yet, but their usage is given in a shell commands script file (see Shell commands file). Run this shell with

./POST_shell_commands.sh

If everything is okay, you should now see output in the Plots/ folder. If an error occurs, please verify whether you have appropriate versions of the external plot programs (i.e. GnuPlot, Bokeh, ...)

Also, open some of the .xmf files in Data/ in VisIt or ParaView to explore these plots.

To finish this tutorial, feel free to adjust some input parameters. For example, you can change the output grid to become 3-D by setting n_zeta_plot and max_zeta_plot, or you could deform it using pert_mult_factor_POST. Figures 3 and 4 were made this way, each from a separate POST run in which only plot_sol_xi is set, and plot_vac_pot for figure 3:

  • figure 3 with n_theta_plot = 401, and the vacuum potential on a finer box with min_Rvac_plot = 1.9, max_Rvac_plot = 5.9, min_Zvac_plot = -1.9, max_Zvac_plot = 1.9 and n_vac_plot = 321 305 (2 minutes on one core);
  • figure 4 with min_r_plot = 0.99, n_theta_plot = 201, n_zeta_plot = 241, max_zeta_plot = 2.0 and without the vacuum potential, which gives the outermost flux surfaces over the whole torus (20 s).
Note
  1. The cylindrical angle \(\varphi\) is often the inverse of the one used in nuclear fusion research, as it can lead to left-handed coordinate systems. In VMEC, it is opted to use it anyway, so it has a left-handed coordinate system. The poloidal angle is chosen to be anticlockwise if you look at a cross-section of the plasma that lies to the right of the \(Z\)-axis with the \(Z\)-axis pointing up, as in PB3D. In PB3D, however, the toroidal angle \(\zeta = - \varphi\) is chosen as the inverse of the cylindrical angle, so it is right-handed.
  2. In the VMEC file of this tutorial, the toroidal flux and the rotational transform are both negative, as in the HELENA equilibrium it was made from, so that \(q\) is negative.
  3. HELENA equilibria are axisymmetric, so PB3D needs only one field line for them. With n_alpha = 64 in the input file, PB3D warns about this, but it still uses 64 field lines, and it then stops because its memory limit max_tot_mem is too low.
