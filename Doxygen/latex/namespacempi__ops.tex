Abort MPI suddenly. 

{\ttfamily MPI\+\_\+\+Abort} ends all the processes of the run. It hands {\ttfamily status} to the launcher ({\ttfamily mpirun}, {\ttfamily srun}, ...), which returns it to the shell as its exit status. A process that was started without a launcher returns {\ttfamily status} itself.

subroutine, public mpi\+\_\+ops::\+stop\+\_\+usage (\begin{DoxyParamCaption}\item[{integer, intent(in)}]{status}{}\end{DoxyParamCaption})}



Stops all processes after the usage or help message. 

Only rank 0 reads the command line, in parse\+\_\+args(). The main programs broadcast the exit status that it returns, and every process then calls this routine. Every process has to call it, because stop\+\_\+\+MPI() makes collective calls: a process that stopped alone would wait in them for the others, which would wait in their next broadcast for it, and the run would never end.

The program ends with exit status {\ttfamily status} and prints nothing more, as the usage or help message has already been printed.

{\footnotesize\ttfamily \label{namespacempi__ops_a40e8610357a9a5b075fef9dab1c3f24f} 
subroutine, public mpi\+\_\+ops::\+sudden\+\_\+stop (\begin{DoxyParamCaption}\item[{integer, intent(in)}]{ierr}{}\end{DoxyParamCaption})}



Suddenly stops the computations, aborting MPI, etc. 

The error code {\ttfamily ierr} is printed and MPI is aborted with abort\+\_\+\+MPI(). The program then ends with the exit status of get\+\_\+exit\+\_\+status(), which is not zero, so that a shell script, a batch system or a test sees that the run failed.

Before the abort, the buffered output on the screen and in the output file is written out: {\ttfamily MPI\+\_\+\+Abort} ends the process without doing this, and the error message would be lost when the output goes to a file or to a pipe.

The stop after the usage or help message is not an error and goes through \doxylink{namespacempi__ops_a6c29c34fa9899fe7b72e85a2bc11df14}{stop\+\_\+usage()}.
