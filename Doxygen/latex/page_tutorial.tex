This page contains a hands-\/on tutorial to get you used to running PB3D to calculate 3-\/D ideal linear high-\/n MHD stability, and POST to post-\/process the results.

Be sure to check out the \doxysectlink{page_installation}{Installation}{0} instruction first.

\hypertarget{page_tutorial_tutorial_eq}{}\doxysection{\texorpdfstring{Getting the Equilibrium}{Getting the Equilibrium}}\label{page_tutorial_tutorial_eq}
PB3D calculates stability of an equilibrium magnetic toroidal configuration. It is written in a modular way to isolate this main task from the actual code that was used to obtain the equilibrium configuration, and the format that this code may use. Currently, two formats are possible:
\begin{DoxyItemize}
\item 3-\/D VMEC \DoxyCite{hirshman1983vmec}{number}{1}.
\item Axisymmetric HELENA \DoxyCite{mikhailovskii1997optimization}{number}{1}.
\end{DoxyItemize}

VMEC is a general 3-\/D code built on an interesting idea: The poloidal coordinate $\theta$ is deformed in such as a way to make the Fourier basis that is used to describe the cylindrical coordinates $R(s,\theta,\varphi)$ and $Z(s,\theta,\varphi)$ as narrow as possible, where $s$ is the flux label ( $s=\Psi_\text{tor}/\Psi_{\text{tor,edge}}$, the normalized toroidal flux) and $\varphi$ is the regular cylindrical angle (\doxylink{page_tutorial_fnt1}{1}). This is done by introducing a deformation factor $\lambda(s,\theta,\varphi)$ defined so that the straight-\/field line coordinate $\theta_\text{F}$ is given by $\theta_\text{F} = \theta + \lambda $.

The fact that $R$, $Z$ and $\lambda$ are given as a double Fourier series in $\theta$ and $\zeta$ ensures that the angular derivatives can be done analytically. This property is used in PB3D. Apart from that, the flux functions that describe the profiles on the flux surfaces, the rotational transform $\iota(s)$ and pressure $p(s)$, are also returned.

For HELENA, the situation is different, as this code considers axisymmetric equilibria only. Its output consists, aside from flux functions safety factor $q(\psi)$, pressure $p(\psi)$ and toroidal covariant magnetic field $F(\psi)$, where $\psi=\Psi_\text{pol}/\Psi_{\text{pol,edge}}$ is the normalized poloidal flux, of a 2-\/D table for the upper metric factors $h^{\psi\psi}$ and $h^{\psi\theta}$ and the lower metric factor $g_{\zeta\zeta}$. HELENA uses the same angular coordinates $\theta$ and $\zeta = -\varphi$ as PB3D (see \doxylink{page_tutorial_fnt1}{1}).

\begin{DoxyNote}{Note}
The modular nature of PB3D enables easy integration of other equilibrium codes, if necessary.
\end{DoxyNote}
To get the appropriate equilibrium code results into PB3D, it suffices to place the output files in the same directory in which PB3D is run:
\begin{DoxyItemize}
\item for HELENA, it is a text file, corresponding to the mapping file ({\ttfamily fort.\+12}),
\item for VMEC, it is the so-\/called {\ttfamily wout} file,
\end{DoxyItemize}

and to specify their names as the second input argument, the first one being the file with user inputs (see \doxysectlink{page_tutorial_tutorial_inputs}{Setting Up the Input File}{1}).

\begin{DoxyNote}{Note}
For VMEC, the {\ttfamily wout} file has to be in Net\+CDF format, and its name has to end in {\ttfamily .nc}, because PB3D recognizes a VMEC file by this extension (see open\+\_\+input()). The {\ttfamily .txt} format of VMEC is not supported.
\end{DoxyNote}

\hypertarget{page_tutorial_tutorial_eq_helena}{}\doxysubsection{\texorpdfstring{Patching HELENA}{Patching HELENA}}\label{page_tutorial_tutorial_eq_helena}
PB3D needs a HELENA that is changed in three places from the usual version. All three are in the subroutine {\ttfamily mapping}, which writes the mapping file {\ttfamily fort.\+12}.
\begin{DoxyEnumerate}
\item HELENA writes {\ttfamily IAS} after {\ttfamily JS0} and {\ttfamily B0} after {\ttfamily RAXIS}. Some versions do not write these by default. If yours is one of them, change 
\begin{DoxyCode}{0}
\DoxyCodeLine{write(nmap,8)\ JS0\ }

\end{DoxyCode}
 to 
\begin{DoxyCode}{0}
\DoxyCodeLine{write(nmap,8)\ JS0,\ IAS\ }

\end{DoxyCode}
 and 
\begin{DoxyCode}{0}
\DoxyCodeLine{write(nmap,8)\ RAXIS\ }

\end{DoxyCode}
 to 
\begin{DoxyCode}{0}
\DoxyCodeLine{write(nmap,8)\ RAXIS,\ B0\ }

\end{DoxyCode}
 Without them, PB3D stops with the error "{}\+Failed to read HELENA output file"{}.
\item HELENA writes the mapping file with 16 significant digits. HELENA\textquotesingle{}s own formats write 8. Change the formats of the mapping output from {\ttfamily E16.\+8} to {\ttfamily E24.\+16}: 
\begin{DoxyCode}{0}
\DoxyCodeLine{6\ FORMAT(4E24.16)}
\DoxyCodeLine{7\ FORMAT(2E24.16)}
\DoxyCodeLine{9\ FORMAT(E24.16)}

\end{DoxyCode}
 (format 11, of the profile file {\ttfamily fort.\+21}, may change the same way; PB3D does not read that file). PB3D reads the file in free format, so it reads both versions without any change.
\item HELENA is compiled in double precision, for example with {\ttfamily gfortran -\/fdefault-\/real-\/8 -\/fdefault-\/double-\/8}. In single precision, 16 written digits do not help.
\end{DoxyEnumerate}

Then recompile and re-\/run HELENA.

The 16 digits are not a claim about the accuracy of the equilibrium. HELENA\textquotesingle{}s own discretisation error changes smoothly from one poloidal point to the next, but rounding to 8 digits adds an independent error of up to $5\times10^{-8}$ at each point. PB3D takes up to three derivatives in the poloidal angle $\chi$, which multiply such an error by about $1/h^3$, with $h$ the spacing of the poloidal points. With 8 digits, the eigenvalue can be off by per cents at low $n$ on fine mappings: with a free boundary at $n = 5$ and 2049 poloidal points, by 2 \% for a circular $\epsilon = 0.33$ case and by 50 \% for a pedestal case (PB3D issue 65). With 16 digits, the same cases converge smoothly in the number of poloidal points. Most of the error comes from the poloidal grid itself: HELENA sets it exactly to $\chi_j = \pi (j-1)/(N_\chi-1)$ (or $2\pi (j-1)/N_\chi$ without up-\/down symmetry), and 8 digits round it.

\begin{DoxyNote}{Note}
PB3D checks this when it reads the file (see read\+\_\+hel() and chi\+\_\+h\+\_\+rounding()). If the poloidal grid in the file differs from HELENA\textquotesingle{}s exact grid by between $10^{-12}$ and $10^{-6}$, PB3D warns that the mapping file has too few digits and refers to this section. The run continues, because the error is small at higher $n$ and on coarse mappings (0.\+1 \% or less at $n \geq 10$ with 1025 poloidal points), but the eigenvalue should not be trusted at low $n$ on fine mappings.
\end{DoxyNote}
\hypertarget{page_tutorial_tutorial_test_eq}{}\doxysection{\texorpdfstring{Checking the equilibrium (optional)}{Checking the equilibrium (optional)}}\label{page_tutorial_tutorial_test_eq}
It is always important that the equilibrium has been properly calculated, well-\/converged, etc.

It is possible to use PB3D to check this. This will be quickly described in this optional section.

The checks described below are only possible with the code compiled in the debug version, which is the CMake option {\ttfamily -\/DPB3\+D\+\_\+\+ENABLE\+\_\+\+DEBUG=ON} (see \doxysectlink{page_installation}{Installation}{0}). Using the debug version, the tests can be triggered using the {\ttfamily -\/-\/test} option when running PB3D (or POST), and using the interactive user interface.

They generally output HDF5 files that can be read with Para\+View or Vis\+It to check the difference between two plots. After having a look in the code (search for {\ttfamily ltest}), this should be self-\/explanatory.

\begin{DoxyNote}{Note}
Most of the checks are only useful for developers. However, the tests on {\ttfamily B\+\_\+F} and on the pressure balance consistency are vital.
\end{DoxyNote}

Have a look:
\begin{DoxyItemize}
\item {\ttfamily min\+\_\+n\+\_\+par\+\_\+X} is the number of points in the parallel grid of every field line at the first Richardson level.
\item These points range from {\ttfamily min\+\_\+par\+\_\+X} to {\ttfamily max\+\_\+par\+\_\+X}, in units of $\pi$.
\item How the field lines are chosen depends on {\ttfamily alpha\+\_\+style}. This file sets {\ttfamily alpha\+\_\+style = 2}, which is also the default for VMEC: PB3D uses {\ttfamily n\+\_\+alpha} field lines, here 64, with equally spaced labels, and follows each of them over one poloidal turn. PB3D sets {\ttfamily min\+\_\+par\+\_\+X} and {\ttfamily max\+\_\+par\+\_\+X} to 0 and 2 if their difference is not 2 (see \doxysectlink{page_inputs}{Input variables}{0}); in this file, they are already 0 and 2.
\item With {\ttfamily alpha\+\_\+style = 1}, the default for HELENA, PB3D follows the single field line with label {\ttfamily alpha}, and the parallel range from {\ttfamily min\+\_\+par\+\_\+X} to {\ttfamily max\+\_\+par\+\_\+X} can span several poloidal turns. For 3-\/D equilibria, the number of field lines {\ttfamily n\+\_\+alpha} ({\ttfamily alpha\+\_\+style = 2}) or the parallel range ({\ttfamily alpha\+\_\+style = 1}), together with {\ttfamily min\+\_\+n\+\_\+par\+\_\+X}, has to be increased until convergence is reached \DoxyCite{weyens2017pb3d}{number}{1}.
\item {\ttfamily n\+\_\+r\+\_\+sol} is the number of points in the solution grid, that ranges from {\ttfamily min\+\_\+r\+\_\+sol} to {\ttfamily max\+\_\+r\+\_\+sol} in the PB3D normal coordinate (see \doxylink{namespacenum__vars_ae21ec57b791e369c3558c0eb3da1555b}{num\+\_\+vars.\+use\+\_\+pol\+\_\+flux\+\_\+f}).
\item {\ttfamily n\+\_\+mod\+\_\+X} is the number of Fourier harmonics that are kept, with {\ttfamily prim\+\_\+X} the primary mode number. With the poloidal flux as normal coordinate (the default), {\ttfamily prim\+\_\+X} is the toroidal mode number $n$ and the harmonics are poloidal mode numbers $m$.
\item {\ttfamily BC\+\_\+style(1:\+2)} indicates the style with which the boundary conditions are implemented deep in the plasma and on the plasma edge.
\item {\ttfamily max\+\_\+tot\+\_\+mem} is a memory limit in MB: PB3D divides its work into jobs so that its own estimate of the memory it needs stays below this limit. The estimate is larger than the memory the run really uses; section \doxysectlink{page_tutorial_tutorial_PB3D_results}{What to expect}{2} gives the numbers for this example. The estimate includes the memory that every process holds before the work starts (MPI, the libraries and the input), about 0.\+1 GB on mac\+OS and 0.\+3 GB on Linux per process. When the limit is too low for the parts of the calculation that cannot be divided, PB3D stops at the start and gives the number of MB it needs.
\item {\ttfamily max\+\_\+it\+\_\+rich} is the number of Richardson levels (see the extra options below); with 1, PB3D does not extrapolate.
\item {\ttfamily use\+\_\+normalization} indicates whether normalization is used (recommended), but it is useful to turn this off for debugging.
\end{DoxyItemize}

\begin{DoxyNote}{Note}
In this file, {\ttfamily BC\+\_\+style = 1 2} makes the plasma edge a free boundary: PB3D calculates the response of the vacuum outside the plasma and adds its energy to the perturbed potential energy (see \doxysectlink{page_overview}{General code structure}{0} and \doxysectlink{page_vacuum}{Vacuum response}{0}). {\ttfamily BC\+\_\+style(2) = 2} is also the default. With {\ttfamily BC\+\_\+style = 1 1}, the displacement is zero at the plasma edge, as if a conducting wall lay on the plasma surface, which makes it a fixed boundary. The inner end, deep in the plasma, only accepts {\ttfamily BC\+\_\+style(1) = 1}. For VMEC, a free boundary needs {\ttfamily alpha\+\_\+style = 2} with more than one field line, as PB3D then uses a 3-\/D boundary-\/element method on the points of the field lines on the plasma boundary; PB3D stops with an error for {\ttfamily alpha\+\_\+style = 1}. The number of field lines decides how well this method resolves the toroidal variation of the vacuum potential, $e^{-in\zeta}$: there must be clearly more than $2n+1$ of them. Section \doxysectlink{page_tutorial_tutorial_PB3D_results}{What to expect}{2} shows how accurate 64 field lines with 100 points each are for this example.
\end{DoxyNote}

\begin{DoxyItemize}
\item {\ttfamily rich\+\_\+restart\+\_\+lvl} is used to restart a simulation at a certain Richardson level. The Richardson level 1 refers to the first simulation, with the number of parallel points used in the calculation of line integrals along the magnetic field set by {\ttfamily min\+\_\+n\+\_\+par\+\_\+X} (see \doxytablelink{page_inputs_inputs_PB3D_file_tab}{inputs\+\_\+\+PB3\+D\+\_\+file\+\_\+tab}). For every subsequent Richardson level, this number $n$ becomes $2n-1$, so that the grid spacing is halved. This tutorial provides a VMEC equilibrium file to experiment with: the {\ttfamily cbm18} equilibrium of the benchmark for edge-\/localized modes of Ferraro et al. \DoxyCite{ferraro2010elmbenchmark}{number}{1}, a nearly circular tokamak with a steep pressure pedestal at the edge, which is unstable to peeling-\/ballooning modes. Put this equilibrium file, as well as the input file in a separate run directory; let\textquotesingle{}s call it {\ttfamily cbm18}.

In order to produce outputs, PB3D needs three sub-\/directories in the run directory, called {\ttfamily Data/}, {\ttfamily Scripts/} and {\ttfamily Plots/}.
\begin{DoxyItemize}
\item In {\ttfamily Data/}, the data files for the external plots are stored, as well as the HDF5 plots ({\ttfamily .h5} and {\ttfamily .xmf} files) that can be read later in visualization software such as Vis\+It or Para\+View.
\item In {\ttfamily Scripts/}, scripts are generated that use the data files from {\ttfamily Data/}.
\item In {\ttfamily Plots/}, the resulting external plots are located. In \doxysectlink{page_outputs_output_plots}{Output Plots}{1}, this is explained in more detail.
\end{DoxyItemize}

If these directories are not present, you will receive an error message, so go ahead and create them.

We can now run the code using {\ttfamily mpirun}. For example, with 
\begin{DoxyCode}{0}
\DoxyCodeLine{mpirun\ -\/np\ 4\ ./PB3D\ PB3D.input\ wout.nc\ }

\end{DoxyCode}
 4 processes are used. With more than one process, the eigenvalue solver needs PETSc with a parallel direct solver such as MUMPS (see \doxysectlink{page_faq}{Frequently Asked Questions}{0}); a single process can also be used, by running {\ttfamily ./\+\+PB3D PB3\+D.\+input wout.\+nc} without {\ttfamily mpirun}. You can find the VMEC file \href{https://pb3d.github.io/Examples/wout.nc}{\texttt{here}}. The HELENA input file of the same plasma is \href{https://pb3d.github.io/Examples/fort.10}{\texttt{here}}; with a HELENA patched as described in \doxysectlink{page_tutorial_tutorial_eq_helena}{Patching HELENA}{2}, it gives the mapping file that PB3D reads instead of {\ttfamily wout.\+nc}.

\begin{DoxyNote}{Note}
On mac\+OS, run PB3D and POST with {\ttfamily Malloc\+Large\+Cache=0} in the environment, for example 
\begin{DoxyCode}{0}
\DoxyCodeLine{MallocLargeCache=0\ ./PB3D\ PB3D.input\ wout.nc\ }

\end{DoxyCode}
 Without it, mac\+OS keeps the memory that PB3D has freed, and PB3D can take about twice {\ttfamily max\+\_\+tot\+\_\+mem}; PB3D warns about this at the start. PB3D cannot set this variable itself, as it has to be set when the program starts.
\end{DoxyNote}
There are optional run-\/time options that can be triggered, such as {\ttfamily --jump\+\_\+to\+\_\+sol}, which can be used to easily change solution preferences, such as discretization order, etc. For an overview, see \doxysectlink{page_inputs_inputs_PB3D_cmd}{Command-\/line inputs}{2}; they are not treated here.

You will see formatted output on the screen, with indentation according to the depth of a routine in the program. The same output is also written to the output file {\ttfamily PB3\+D\+\_\+out.\+txt}, unformatted but still indented (see \doxysectlink{page_outputs_output_file_log}{Log file}{2}).

The resulting eigenvalues can also be read in a separate output file, {\ttfamily PB3\+D\+\_\+out\+\_\+\+EV\+\_\+\+R\+\_\+1.\+txt} for the first Richardson level (see \doxysectlink{page_outputs_output_file_EV}{Eigenvalue summary file}{2}). The other results are written to the HDF5 file {\ttfamily PB3\+D\+\_\+out.\+h5}, which POST reads.

Take a look at these output files and shuffle a bit with the input parameters if you want. For example, change {\ttfamily n\+\_\+mod\+\_\+X} to another value in order to get a different number of Fourier harmonics, or {\ttfamily n\+\_\+r\+\_\+sol} to change the number of normal grid points in the solution. The solution should not change a lot if you have enough harmonics and normal grid points.

\begin{DoxyNote}{Note}
For VMEC, the magnetic axis is a bit problematic. It is necessary, therefore, to choose {\ttfamily min\+\_\+r\+\_\+sol} to be slightly larger than 0; 0.\+01 for example.
\end{DoxyNote}
\hypertarget{page_tutorial_tutorial_PB3D_results}{}\doxysubsection{\texorpdfstring{What to expect}{What to expect}}\label{page_tutorial_tutorial_PB3D_results}
On one core of a laptop (Apple M3 Pro, with {\ttfamily Malloc\+Large\+Cache=0}), this run takes about 2.\+5 minutes, and its memory use peaks at 4.\+0 GB, below the limit {\ttfamily max\+\_\+tot\+\_\+mem} of 8000 MB. Most of the time goes into the plasma quantities on the 64 field lines, which PB3D divides into 25 equilibrium jobs; the vacuum takes 10 s. This input file needs a {\ttfamily max\+\_\+tot\+\_\+mem} of at least 5.\+7 GB on this laptop with one process, and about 7.\+4 GB on Linux with 4 processes: the vacuum matrices exist in every equilibrium job and in the solution driver, and the integrated perturbation quantities in the solution driver, which cannot be divided into jobs, and every process holds memory of its own. With a lower limit, PB3D stops at the start and gives the number it needs.

PB3D gives the eigenvalues $\lambda = \omega^2/\omega_A^2$, normalized to the square of the Alfvén frequency $\omega_A$ that the header of {\ttfamily PB3\+D\+\_\+out\+\_\+\+EV\+\_\+\+R\+\_\+1.\+txt} gives. For this input file, the first eigenvalue should be close to $\lambda = -0.0499$. A negative eigenvalue belongs to an unstable mode, with the growth rate $\gamma = \omega_A\sqrt{-\lambda}$, here $0.22\,\omega_A$.

Figure 2 shows the eigenvector: the amplitudes of the poloidal Fourier harmonics $X_m$ of the normal displacement $X = \vec{\xi}\cdot\nabla\psi$. Each harmonic peaks close to the flux surface on which it is resonant, where $n|q| = m$; the upper axis of the figure gives $n|q|$. The largest harmonics, $m = 18$ to $23$, lie where the pressure falls most steeply. At the plasma boundary, where $n|q| = 30.4$, the harmonic $m = 31$, which would be resonant just outside the plasma, still has 0.\+27 of the largest amplitude, so that the mode moves the boundary.

An interesting output is the energy reconstruction, which is activated with {\ttfamily plot\+\_\+\+E\+\_\+rec}. This calculation reinserts the eigenvector into the terms of the perturbed potential energy and of the kinetic energy, in order to check whether the Rayleigh quotient still holds, and to see which terms are dominant and which ones are less important. The integrated terms are also stored in a separate file, {\ttfamily POST\+\_\+out\+\_\+\+EN\+\_\+R\+[lvl].txt} for Richardson level {\ttfamily \+[lvl]} (see \doxysectlink{page_outputs_output_file_E_rec}{Energy reconstruction file}{2}).

Figure 5 shows these terms for this example, divided by the kinetic energy, so that they add up to the eigenvalue: their sum, $-0.04984$, differs from the eigenvalue $-0.04987$ by $7\times10^{-4}$ of its value. The normal ballooning term, which holds the pressure gradient and the normal curvature of the field lines, drives the mode most, and the line bending terms stabilize it. The figure also shows the terms of the fixed-\/boundary run ({\ttfamily BC\+\_\+style = 1 1}). The vacuum term itself is small and positive, $+0.005$. The free boundary makes the mode more unstable because the eigenvector changes: with the free boundary, the normal ballooning term is more negative by 0.\+025 and the normal kink term, which holds the parallel current, by 0.\+012, while the line bending terms grow by 0.\+027.

\begin{DoxyNote}{Note}

\begin{DoxyEnumerate}
\item \label{page_tutorial_fnt1}%
\Hypertarget{page_tutorial_fnt1}%
The cylindrical angle $\varphi$ is often the inverse of the one used in nuclear fusion research, as it can lead to left-\/handed coordinate systems. In VMEC, it is opted to use it anyway, so it has a left-\/handed coordinate system. The poloidal angle is chosen to be anticlockwise if you look at a cross-\/section of the plasma that lies to the right of the $Z$-\/axis with the $Z$-\/axis pointing up, as in PB3D. In PB3D, however, the toroidal angle $\zeta = - \varphi$ is chosen as the inverse of the cylindrical angle, so it is right-\/handed.
\item \label{page_tutorial_fnt2}%
\Hypertarget{page_tutorial_fnt2}%
In the VMEC file of this tutorial, the toroidal flux and the rotational transform are both negative, as in the HELENA equilibrium it was made from, so that $q$ is negative.
\item \label{page_tutorial_fnt3}%
\Hypertarget{page_tutorial_fnt3}%
HELENA equilibria are axisymmetric, so PB3D needs only one field line for them. With {\ttfamily n\+\_\+alpha = 64} in the input file, PB3D warns about this, but it still uses 64 field lines, and it then stops because its memory limit {\ttfamily max\+\_\+tot\+\_\+mem} is too low. 
\end{DoxyEnumerate}
\end{DoxyNote}
