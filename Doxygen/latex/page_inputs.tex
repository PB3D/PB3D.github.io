\chapter{Input variables }
\hypertarget{page_inputs}{}\label{page_inputs}\index{Input variables@{Input variables}}
 
    \textit{\scriptsize Footnotes are situated at the end of the chapter}


This page describes the input variables of PB3D and POST.

Most inputs are read from the user input file, which holds the Fortran namelist {\ttfamily inputdata\+\_\+\+PB3D} for PB3D or {\ttfamily inputdata\+\_\+\+POST} for POST. Every variable that is not set in the file keeps its default value. A name in the file that is not part of the namelist stops the program with the error "{}\+Cannot read user-\/provided file"{}. The other inputs are options on the command line. PB3D and POST are called as \begin{DoxyVerb}PB3D USER_INPUT EQUILIBRIUM_INPUT [OPTIONS]
POST USER_INPUT PB3D_OUTPUT [OPTIONS]
\end{DoxyVerb}
 where the options take the form {\ttfamily --\+[option\+\_\+name]}, sometimes followed by values. If the user input file cannot be opened, the program uses the defaults for all variables. \begin{DoxySeeAlso}{See also}
See init\+\_\+files() and open\+\_\+input().
\end{DoxySeeAlso}
For both PB3D and POST, both types of input are discussed.

Some general remarks:
\begin{DoxyItemize}
\item There is some fault detection built into the routines. These distinguish between minor faults, which trigger a warning but do not stop execution, and major faults, which trigger an error that stops execution. \begin{DoxySeeAlso}{See also}
See writo().
\end{DoxySeeAlso}

\item The data type {\ttfamily real} refers to double precision real, defined by \doxylink{namespacenum__vars_a03802aa2bd86439d7a9370836fabf3f2}{num\+\_\+vars.\+dp}. For integers, standard precision is used. A type such as {\ttfamily int(2)} is an array of two values, given in the input file as two numbers separated by a space.
\item Angles are given in units of $\pi$, marked $\left[\pi\right]$.
\item PB3D takes a file with the extension {\ttfamily .nc} as a VMEC file, which gives {\ttfamily eq\+\_\+style = 1}, and a file that starts with an integer as a HELENA file, which gives {\ttfamily eq\+\_\+style = 2}. Several defaults depend on {\ttfamily eq\+\_\+style}. POST reads {\ttfamily eq\+\_\+style} from the PB3D output.
\item PB3D limits the tolerances {\ttfamily tol\+\_\+rich}, {\ttfamily tol\+\_\+zero} and {\ttfamily tol\+\_\+\+SLEPC} to the range from {\ttfamily min\+\_\+tol} $= 10^{-12}$ to {\ttfamily max\+\_\+tol} $= 10^{-3}$, which are hard-\/coded in read\+\_\+input\+\_\+opts().
\item If {\ttfamily eq\+\_\+style = 2} (i.\+e. HELENA), the total maximum memory available must be enough to perform the first Richardson level in a single equilibrium job (see \doxysectlink{page_overview}{General code structure}{0}).
\item PB3D computes the vacuum response only for a free boundary, {\ttfamily BC\+\_\+style(2) = 2}. No input chooses the vacuum style. PB3D takes the field-\/line 3-\/D style for a VMEC equilibrium and the axisymmetric style for a HELENA equilibrium (see \doxylink{page_inputs_fni37}{37}).
\end{DoxyItemize}\hypertarget{page_inputs_inputs_PB3D}{}\doxysection{\texorpdfstring{PB3D Inputs}{PB3D Inputs}}\label{page_inputs_inputs_PB3D}

For a VMEC equilibrium, PB3D uses the field-\/line 3-\/D style (style 1): a boundary-\/element method on the points of the field lines on the plasma boundary. It needs several field lines, so a free-\/boundary VMEC run with {\ttfamily alpha\+\_\+style = 1} stops with an error; PB3D computes the vacuum at every Richardson level. For a HELENA equilibrium, PB3D uses the axisymmetric style (style 2), with toroidal functions on the boundary of the poloidal cross-\/section, and it computes the vacuum once, at the first Richardson level of the run ({\ttfamily rich\+\_\+restart\+\_\+lvl}). PB3D solves the boundary-\/element system with STRUMPACK if it was built with STRUMPACK, and with the Sca\+LAPACK LU factorization otherwise (see \doxysectlink{page_installation}{Installation}{0}).
\item \label{page_inputs_fni38}%
\Hypertarget{page_inputs_fni38}%
The check runs inside calc\+\_\+vac\+\_\+res(), so only when PB3D computes the vacuum (see \doxylink{page_inputs_fni37}{37}). check\+\_\+vac\+\_\+exact() tests the boundary-\/element matrices on the plasma boundary of the equilibrium with potentials that are harmonic inside the boundary (the constant, the Cartesian coordinates $x$, $y$, $z$, and $x^2 - y^2$) and with potentials that are harmonic outside it and decay (a point source on the magnetic axis and a ring of point sources along the axis). It prints the residuals of the Green identities, the errors of the exterior solution and the differences between the assembled diagonals and the alternative ones on lines of the log that start with {\ttfamily CHECKVAC}. It also writes the values at the boundary points to files {\ttfamily check\+\_\+vac\+\_\+\texorpdfstring{$\ast$}{*}.dat} in the run directory.
\item \label{page_inputs_fni39}%
\Hypertarget{page_inputs_fni39}%
For the field-\/line style, the indirect diagonals follow from the row sums for the constant and the linear interior harmonics; for the axisymmetric style, they follow from the identities of two known potentials, the two solutions of the Legendre equation of a ring at the centroid of the boundary, solved exactly at every point (diag\+\_\+indirect()). The direct diagonals use the corner term and the integral of the kernel over the cell of the node (calc\+\_\+diag\+\_\+direct() for the field-\/line style). Style 1 is the more accurate of the two, and PB3D prints a warning that style 2 is a diagnostic, not meant for production runs, when it is used with a free boundary. With {\ttfamily check\+\_\+vac}, PB3D reports the difference between the assembled diagonal and the other one at every point. A value other than 1 or 2 stops PB3D with an error message.
\item \label{page_inputs_fni40}%
\Hypertarget{page_inputs_fni40}%
POST plots the vacuum potential only for a free boundary; for a fixed boundary it switches {\ttfamily plot\+\_\+vac\+\_\+pot} off. It evaluates the potential in the planes of constant $\zeta$ of the plasma plots ({\ttfamily n\+\_\+zeta\+\_\+plot} planes from {\ttfamily min\+\_\+zeta\+\_\+plot} to {\ttfamily max\+\_\+zeta\+\_\+plot}), on a grid of {\ttfamily n\+\_\+vac\+\_\+plot(1)} by {\ttfamily n\+\_\+vac\+\_\+plot(2)} points in $R$ and $Z$. If {\ttfamily max\+\_\+\+Rvac\+\_\+plot} is not larger than {\ttfamily min\+\_\+\+Rvac\+\_\+plot}, which is the case for the defaults, the range in $R$ is the range of the boundary points widened on both sides by half the larger of the widths of the boundary in $R$ and in $Z$, and it starts at no less than 0.\+1 times the smallest $R$ of the boundary; the same rule with {\ttfamily min\+\_\+\+Zvac\+\_\+plot} and {\ttfamily max\+\_\+\+Zvac\+\_\+plot} sets the range in $Z$. A range given by the user must have a positive {\ttfamily min\+\_\+\+Rvac\+\_\+plot}. The limits are in metres. For a HELENA equilibrium without a user-\/given {\ttfamily R\+\_\+0}, PB3D sets {\ttfamily R\+\_\+0 = 1}, and the limits are then in units of the length scale of the HELENA equilibrium. See vac\+\_\+pot\+\_\+plot() for the output.
\item \label{page_inputs_fni41}%
\Hypertarget{page_inputs_fni41}%
The four values are the number of the first unstable solutions, of the last unstable solutions, of the first stable solutions and of the last stable solutions that POST plots. A negative value means all solutions of that range. See find\+\_\+stab\+\_\+ranges().
\item \label{page_inputs_fni42}%
\Hypertarget{page_inputs_fni42}%
PB3D recognizes these PETSc and SLEPC options so that it does not warn about them. PETSc and SLEPC read them from the command line themselves; SLEPC reads the solver options in EPSSet\+From\+Options(), which get\+\_\+solution() calls after the solver has been set up, so that they override the settings of {\ttfamily solver\+\_\+\+SLEPC\+\_\+style}, {\ttfamily tol\+\_\+\+SLEPC} and {\ttfamily max\+\_\+it\+\_\+\+SLEPC}. These options start with a single dash.
\item \label{page_inputs_fni43}%
\Hypertarget{page_inputs_fni43}%
For {\ttfamily alpha\+\_\+style = 1}, PB3D follows the single field line with label {\ttfamily alpha} from {\ttfamily min\+\_\+par\+\_\+X} to {\ttfamily max\+\_\+par\+\_\+X}, and it sets {\ttfamily n\+\_\+alpha} to 1. For {\ttfamily alpha\+\_\+style = 2}, PB3D uses {\ttfamily n\+\_\+alpha} field lines with the labels $\alpha_j = 2\pi (j-1)/n_\alpha$, $j = 1 \ldots n_\alpha$, ignores {\ttfamily alpha}, and resets {\ttfamily min\+\_\+par\+\_\+X} and {\ttfamily max\+\_\+par\+\_\+X} to 0 and 2 if they do not span one poloidal turn. A free boundary with a VMEC equilibrium needs {\ttfamily alpha\+\_\+style = 2}. PB3D warns when {\ttfamily n\+\_\+alpha} and the number of field periods $N_\text{fp}$ of the VMEC equilibrium have a common factor, because the sum over the field lines then adds the toroidal harmonic of order $\mathrm{LCM}(n_\alpha, N_\text{fp})$ of the equilibrium to the average; {\ttfamily n\+\_\+alpha} should be chosen coprime to $N_\text{fp}$. For the field-\/line 3-\/D vacuum, the convergence studies in README.\+md of the code recommend at least 128 field lines and about 36 parallel points per poloidal wavelength of the perturbation. For HELENA equilibria, which are axisymmetric, PB3D warns if {\ttfamily n\+\_\+alpha} is larger than 1 or if {\ttfamily min\+\_\+par\+\_\+X} and {\ttfamily max\+\_\+par\+\_\+X} do not span exactly one poloidal turn.
\item \label{page_inputs_fni44}%
\Hypertarget{page_inputs_fni44}%
PB3D raises {\ttfamily n\+\_\+r\+\_\+sol} to at least {\ttfamily 6 norm\+\_\+disc\+\_\+prec\+\_\+sol + 2}, and to at least {\ttfamily (2 norm\+\_\+disc\+\_\+prec\+\_\+sol + 1)} times the number of MPI processes. For a free boundary with {\ttfamily norm\+\_\+disc\+\_\+prec\+\_\+sol} 2 or 3, the last points of the solution grid carry the weights of \doxylink{namespacenum__utilities_ad2f180cb684bc4bb965e3e07b26a92dc}{num\+\_\+utilities.\+calc\+\_\+end\+\_\+weights()} in the normal integral.
\item \label{page_inputs_fni45}%
\Hypertarget{page_inputs_fni45}%
A value below 1 is replaced by the number of MPI processes, and a value above the number of MPI processes is lowered to it, with a warning.
\item \label{page_inputs_fni46}%
\Hypertarget{page_inputs_fni46}%
Up to 100 values can be given. If fewer values than {\ttfamily max\+\_\+it\+\_\+rich} are given, the remaining levels get $10^{-5}$; values beyond {\ttfamily max\+\_\+it\+\_\+rich} are discarded.
