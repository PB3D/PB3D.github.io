\chapter{Installation }
\hypertarget{page_installation}{}\label{page_installation}\index{Installation@{Installation}}
\hypertarget{page_installation_installation_introduction}{}\doxysection{\texorpdfstring{Introduction}{Introduction}}\label{page_installation_installation_introduction}
PB3D is written in Fortran and is built with \href{https://cmake.org/}{\texttt{CMake}}. It makes use of the following external libraries:
\begin{DoxyItemize}
\item \href{https://www.mpi-forum.org/}{\texttt{MPI}}
\begin{DoxyItemize}
\item for the parallel processes
\end{DoxyItemize}
\item \href{https://petsc.org/}{\texttt{PETSc}} / \href{https://slepc.upv.es/}{\texttt{SLEPc}}, built with complex scalars
\begin{DoxyItemize}
\item for the large, sparse matrices of the eigenvalue problem and for its solution
\end{DoxyItemize}
\item \href{https://mumps-solver.org/}{\texttt{MUMPS}}, through PETSc
\begin{DoxyItemize}
\item for the distributed LU factorization in the eigenvalue solver, which is needed to run PB3D on more than one MPI process
\end{DoxyItemize}
\item \href{https://www.hdfgroup.org/solutions/hdf5/}{\texttt{HDF5}}, parallel and with Fortran bindings
\begin{DoxyItemize}
\item for the output files
\end{DoxyItemize}
\item \href{https://www.unidata.ucar.edu/software/netcdf/}{\texttt{Net\+CDF-\/\+Fortran}}
\begin{DoxyItemize}
\item to read the output of VMEC
\end{DoxyItemize}
\item \href{http://www.netlib.org/lapack/}{\texttt{BLAS / LAPACK}} and \href{http://www.netlib.org/scalapack/}{\texttt{Sca\+LAPACK}}
\begin{DoxyItemize}
\item for dense linear algebra, in particular the boundary-\/element system of the vacuum
\end{DoxyItemize}
\item \href{https://github.com/PrincetonUniversity/STELLOPT}{\texttt{LIBSTELL}}, part of the STELLOPT suite, which contains VMEC
\begin{DoxyItemize}
\item to read the output of VMEC (PB3D uses only the module {\ttfamily read\+\_\+wout\+\_\+mod})
\end{DoxyItemize}
\item \href{https://github.com/ilonster/pspline}{\texttt{PSPLINE}}
\begin{DoxyItemize}
\item Princeton Spline and Hermite Cubic Interpolation Routines
\end{DoxyItemize}
\item STRUMPACK-\/\+Dense 1.\+1.\+1 (optional)
\begin{DoxyItemize}
\item for a compressed solver of the boundary-\/element system of the vacuum \DoxyCite{ambikasaran2013}{number}{1}; without it, PB3D solves that system with the LU factorization of Sca\+LAPACK
\end{DoxyItemize}
\end{DoxyItemize}

Furthermore, PB3D comes bundled with some other, smaller libraries, which CMake compiles with the code:
\begin{DoxyItemize}
\item \href{http://www.netlib.org/fftpack/}{\texttt{fftpack}} ({\ttfamily Libraries/\+dfft.\+f})
\begin{DoxyItemize}
\item to calculate the fast Fourier transform
\end{DoxyItemize}
\item \href{http://foul.sourceforge.net/}{\texttt{foul}} ({\ttfamily Libraries/\+foul.\+f90})
\begin{DoxyItemize}
\item the Fortran Output Library
\end{DoxyItemize}
\item \href{https://github.com/fortran-lang/test-drive}{\texttt{test-\/drive}} ({\ttfamily tests/\+vendor/\+test-\/drive})
\begin{DoxyItemize}
\item the framework of the unit tests
\end{DoxyItemize}
\end{DoxyItemize}

PB3D can be obtained using git: \begin{DoxyVerb}git clone https://github.com/ToonWeyens/PB3D.git
\end{DoxyVerb}


The commands below use two shell variables. {\ttfamily PB3\+D\+\_\+\+SRC} is the directory of this clone, and {\ttfamily DEPS} is a directory in which the dependencies that are built by hand are kept. \begin{DoxyVerb}export PB3D_SRC=$PWD/PB3D
export DEPS=$HOME/pb3d-deps
mkdir -p $DEPS
\end{DoxyVerb}
\hypertarget{page_installation_installation_requirements}{}\doxysection{\texorpdfstring{Requirements}{Requirements}}\label{page_installation_installation_requirements}
The build needs the following tools:
\begin{DoxyItemize}
\item A Fortran compiler, and a C and a C++ compiler. The builds that are tested use GNU Fortran 13, 14.\+2 and 16. {\ttfamily CMake\+Lists.\+txt} also contains flags for the Intel Fortran compiler.
\item CMake 3.\+18 or later. With PETSc 3.\+25, use CMake 4 (see \doxysectlink{page_installation_installation_problems}{Known problems}{1}).
\item An MPI library with Fortran, C and C++ bindings, such as Open\+MPI.
\item pkg-\/config. CMake finds PETSc, SLEPc and Net\+CDF-\/\+Fortran through pkg-\/config, and Sca\+LAPACK through pkg-\/config or by the library name.
\item xz, to decompress the equilibrium files of the regression tests.
\item Optionally Python 3 with h5py and scipy, for the checks of the regression tests that read the HDF5 output.
\end{DoxyItemize}

PETSc must be built with complex scalars and double precision. The PETSc versions that are tested are 3.\+19, with SLEPc 3.\+19, and 3.\+25.\+3, with SLEPc 3.\+25.\+1. PETSc and SLEPc must have the same minor version.\hypertarget{page_installation_installation_dependencies}{}\doxysection{\texorpdfstring{Dependencies}{Dependencies}}\label{page_installation_installation_dependencies}
PETSc, SLEPc, HDF5, Net\+CDF-\/\+Fortran and Sca\+LAPACK can come from the packages of a Linux distribution (\doxysectlink{page_installation_installation_deps_apt}{Ubuntu packages}{2}), from Spack (\doxysectlink{page_installation_installation_deps_spack}{Spack}{2}), or from a build from source, which is the usual route on a cluster (\doxysectlink{page_installation_installation_deps_source}{PETSc and SLEPc from source}{2}). PSPLINE and LIBSTELL are built by hand in all cases, with the scripts in the directory {\ttfamily Libraries} of the code (\doxysectlink{page_installation_installation_pspline}{PSPLINE}{2} and \doxysectlink{page_installation_installation_libstell}{LIBSTELL}{2}).\hypertarget{page_installation_installation_deps_apt}{}\doxysubsection{\texorpdfstring{Ubuntu packages}{Ubuntu packages}}\label{page_installation_installation_deps_apt}
On Ubuntu 24.\+04, which the continuous integration of PB3D uses, the packages are installed with \begin{DoxyVerb}sudo apt-get install gfortran g++ cmake pkg-config xz-utils \
    libopenmpi-dev openmpi-bin \
    libpetsc-complex3.19-dev libslepc-complex3.19-dev \
    libhdf5-openmpi-dev libnetcdff-dev \
    liblapack-dev libblas-dev libscalapack-openmpi-dev
export PETSC_DIR=/usr/lib/petscdir/petsc3.19/x86_64-linux-gnu-complex
export SLEPC_DIR=/usr/lib/slepcdir/slepc3.19/x86_64-linux-gnu-complex
export PKG_CONFIG_PATH=$PETSC_DIR/lib/pkgconfig:$SLEPC_DIR/lib/pkgconfig
export NETCDF_FORTRAN_DIR=/usr
\end{DoxyVerb}
 The parallel HDF5 of these packages is selected at the configuration of PB3D with {\ttfamily -\/DHDF5\+\_\+\+ROOT=/\+usr/\+lib/\+x86\+\_\+64-\/linux-\/gnu/\+hdf5/\+openmpi}. The continuous integration solves the eigenvalue problem with these packages on one process only. Whether a PETSc has MUMPS can be checked in the file {\ttfamily petscconf.\+h} of PETSc, which defines {\ttfamily PETSC\+\_\+\+HAVE\+\_\+\+MUMPS} if it has: \begin{DoxyVerb}grep PETSC_HAVE_MUMPS $PETSC_DIR/include/petscconf.h
\end{DoxyVerb}
\hypertarget{page_installation_installation_deps_spack}{}\doxysubsection{\texorpdfstring{Spack}{Spack}}\label{page_installation_installation_deps_spack}
The file {\ttfamily spack.\+yaml} in the code describes a \href{https://spack.readthedocs.io/}{\texttt{Spack}} environment with PETSc 3.\+25 (complex scalars), SLEPc 3.\+25, parallel HDF5 with Fortran bindings, Net\+CDF-\/\+Fortran, Sca\+LAPACK and pkg-\/config. It was tested with GCC 16 and Open\+MPI 5 on mac\+OS (Apple Silicon). On mac\+OS, Apple Clang has no Fortran compiler, so GCC has to be installed first, for example with Homebrew ({\ttfamily brew install gcc}). The environment is created and built with \begin{DoxyVerb}git clone https://github.com/spack/spack.git $DEPS/spack
. $DEPS/spack/share/spack/setup-env.sh
spack compiler find
spack external find cmake openmpi gmake perl python
cd $PB3D_SRC
spack env create pb3d-env spack.yaml
spack env activate pb3d-env
spack concretize -f
spack install
export NETCDF_FORTRAN_DIR=$(spack location -i netcdf-fortran)
\end{DoxyVerb}
 The command {\ttfamily spack external find} lets Spack use the MPI library and the tools that are already installed instead of building them. The first {\ttfamily spack install} takes a long time, because it builds PETSc and SLEPc with their dependencies. With the environment active, pkg-\/config and CMake find the libraries of the environment. The PETSc of {\ttfamily spack.\+yaml} has no MUMPS, so PB3D runs with it on one process only.\hypertarget{page_installation_installation_deps_source}{}\doxysubsection{\texorpdfstring{PETSc and SLEPc from source}{PETSc and SLEPc from source}}\label{page_installation_installation_deps_source}
A build from source is needed when no PETSc with complex scalars is available, which is often the case on clusters, or when PB3D has to run on more than one process and the available PETSc has no MUMPS. The compilers, MPI, BLAS/\+\+LAPACK, Sca\+LAPACK, parallel HDF5 and Net\+CDF-\/\+Fortran then come from the system, for example from its environment modules. The following recipe was tested with PETSc 3.\+25.\+3, which downloads and builds MUMPS, Par\+METIS and METIS itself, and SLEPc 3.\+25.\+1. The options {\ttfamily --with-\/blaslapack-\/lib} and {\ttfamily --with-\/scalapack-\/lib} must point to the libraries of the system; the values below are examples. \begin{DoxyVerb}cd $DEPS
curl -L -O https://web.cels.anl.gov/projects/petsc/download/release-snapshots/petsc-3.25.3.tar.gz
tar xzf petsc-3.25.3.tar.gz
cd petsc-3.25.3
export PETSC_DIR=$PWD PETSC_ARCH=arch-complex-opt
./configure --prefix=$DEPS/petsc \
    --with-scalar-type=complex --with-precision=double --with-debugging=0 \
    --with-cc=mpicc --with-cxx=mpicxx --with-fc=mpif90 \
    --with-blaslapack-lib="-L/path/to/blas/lib -lopenblas" \
    --with-scalapack-lib="-L/path/to/scalapack/lib -lscalapack" \
    --download-mumps --download-parmetis --download-metis \
    --with-fortran-bindings=1 --with-shared-libraries=1 --with-x=0 \
    COPTFLAGS=-O2 CXXOPTFLAGS=-O2 FOPTFLAGS=-O2
make all
make install

cd $DEPS
curl -L -O https://slepc.upv.es/download/distrib/slepc-3.25.1.tar.gz
tar xzf slepc-3.25.1.tar.gz
cd slepc-3.25.1
export PETSC_DIR=$DEPS/petsc SLEPC_DIR=$PWD
unset PETSC_ARCH
./configure --prefix=$DEPS/slepc
make
make install

export PKG_CONFIG_PATH=$DEPS/petsc/lib/pkgconfig:$DEPS/slepc/lib/pkgconfig:$PKG_CONFIG_PATH
\end{DoxyVerb}
 PETSc then uses MUMPS for the distributed LU factorization without any setting in PB3D. The build of PETSc with MUMPS takes about half an hour on 16 cores. The code contains the scripts that build PB3D in this way on one cluster, in the directory {\ttfamily scripts/\+snellius}; their paths and modules are those of that cluster.\hypertarget{page_installation_installation_pspline}{}\doxysubsection{\texorpdfstring{PSPLINE}{PSPLINE}}\label{page_installation_installation_pspline}
The script {\ttfamily Libraries/\+build\+\_\+pspline.\+sh} builds PSPLINE with gfortran, without Net\+CDF, from a clone of \href{https://github.com/ilonster/pspline}{\texttt{github.\+com/\+ilonster/\+pspline}}. It first applies the patch {\ttfamily Libraries/\+pspline-\/r8genxpkg-\/nx3.\+patch}, which has to lie next to the script. The patch stops the routine {\ttfamily r8genxpkg} from writing 8 bytes past the end of its array for three unevenly spaced points; PB3D calls it with such points, and without the patch about every other run crashes on mac\+OS. The script is copied into the clone and run there: \begin{DoxyVerb}git clone --depth 1 https://github.com/ilonster/pspline.git $DEPS/pspline
cp $PB3D_SRC/Libraries/build_pspline.sh $PB3D_SRC/Libraries/pspline-r8genxpkg-nx3.patch $DEPS/pspline/
$DEPS/pspline/build_pspline.sh
export PSPLINE_DIR=$DEPS/pspline/install
\end{DoxyVerb}
 The library and the module files are then in {\ttfamily \$\+DEPS/\+pspline/\+install/\+lib} and {\ttfamily \$\+DEPS/\+pspline/\+install/\+include}.\hypertarget{page_installation_installation_libstell}{}\doxysubsection{\texorpdfstring{LIBSTELL}{LIBSTELL}}\label{page_installation_installation_libstell}
PB3D uses only the module {\ttfamily read\+\_\+wout\+\_\+mod} of LIBSTELL. The script {\ttfamily Libraries/\+build\+\_\+libstell\+\_\+min.\+sh} compiles this module and the modules it depends on from a clone of STELLOPT into a small static library. It needs {\ttfamily mpif90} and Net\+CDF-\/\+Fortran; {\ttfamily NETCDF\+\_\+\+FORTRAN\+\_\+\+DIR} is the installation directory of Net\+CDF-\/\+Fortran, which contains {\ttfamily include/\+netcdf.\+inc}. \begin{DoxyVerb}git clone --depth 1 https://github.com/PrincetonUniversity/STELLOPT.git $DEPS/stellopt
STELLOPT_SRC=$DEPS/stellopt NETCDF_FORTRAN_DIR=$NETCDF_FORTRAN_DIR \
    $PB3D_SRC/Libraries/build_libstell_min.sh $DEPS/libstell-min
export LIBSTELL_DIR=$DEPS/libstell-min
\end{DoxyVerb}
 The last argument of the script is the installation directory. It should always be given, because the default of the script assumes that the code lies in {\ttfamily \$\+HOME/\+\+Code/\+\+PB3D}. Both scripts put {\ttfamily /\+opt/\+homebrew/\+bin} at the front of {\ttfamily PATH}, so on mac\+OS they use the compilers of Homebrew. A full LIBSTELL, built with the build system of STELLOPT, works as well. CMake looks under {\ttfamily LIBSTELL\+\_\+\+DIR} (or {\ttfamily STELLOPT\+\_\+\+DIR}) for the library {\ttfamily libstell} and for the module file {\ttfamily vsvd0.\+mod} or {\ttfamily vmec\+\_\+input.\+mod}.\hypertarget{page_installation_installation_strumpack}{}\doxysubsection{\texorpdfstring{STRUMPACK-\/\+Dense (optional)}{STRUMPACK-\/\+Dense (optional)}}\label{page_installation_installation_strumpack}
Without STRUMPACK, PB3D solves the boundary-\/element system of the vacuum with the LU factorization of Sca\+LAPACK ({\ttfamily pdgetrf} and {\ttfamily pdgetrs}). The continuous integration and the cluster builds use this solver. PB3D can use the old STRUMPACK-\/\+Dense 1.\+1.\+1 instead, through its Fortran module {\ttfamily strumpackdensepackage}, which the newer STRUMPACK 7 does not have. The source, {\ttfamily STRUMPACK-\/\+Dense-\/1.\+1.\+1.\+tar.\+gz}, comes from {\ttfamily portal.\+nersc.\+gov/\+project/\+sparse/\+strumpack}, which is not always reachable. In the directory {\ttfamily src} of the unpacked package, the two sources are compiled into a library: \begin{DoxyVerb}mpic++ -O3 -std=gnu++11 -I. -c StrumpackDensePackage_C.cpp -o StrumpackDensePackage_C.o
mpif90 -O3 -c StrumpackDensePackage.F90 -o StrumpackDensePackage.o
ar -rcs libstrumpack.a StrumpackDensePackage_C.o StrumpackDensePackage.o
\end{DoxyVerb}
 The MPI C++ compiler must use the GNU C++ compiler (for Open\+MPI, with {\ttfamily OMPI\+\_\+\+CXX=g++}), because PB3D links with {\ttfamily -\/lstdc++}. CMake looks for {\ttfamily libstrumpack.\+a} in the subdirectory {\ttfamily lib} or {\ttfamily src} of {\ttfamily STRUMPACK\+\_\+\+DIR}, and for {\ttfamily strumpackdensepackage.\+mod} in the subdirectory {\ttfamily inc} or {\ttfamily examples}. Links in {\ttfamily lib} and {\ttfamily inc} of the package directory to the two files in {\ttfamily src} satisfy this, and {\ttfamily STRUMPACK\+\_\+\+DIR} is then the package directory.\hypertarget{page_installation_installation_compilation}{}\doxysection{\texorpdfstring{Compilation with CMake}{Compilation with CMake}}\label{page_installation_installation_compilation}
When all dependencies are available, PB3D is configured and compiled in a separate build directory: \begin{DoxyVerb}cmake -S $PB3D_SRC -B $PB3D_SRC/build \
    -DCMAKE_BUILD_TYPE=Release \
    -DPSPLINE_DIR=$PSPLINE_DIR \
    -DLIBSTELL_DIR=$LIBSTELL_DIR
cmake --build $PB3D_SRC/build -j
\end{DoxyVerb}
 With the Ubuntu packages, the configuration also needs {\ttfamily -\/DHDF5\+\_\+\+ROOT=/\+usr/\+lib/\+x86\+\_\+64-\/linux-\/gnu/\+hdf5/\+openmpi}. At the end of the configuration, CMake prints a summary of the dependencies it found, including whether it found STRUMPACK. The executables {\ttfamily PB3D} and {\ttfamily POST} are created in the build directory. {\ttfamily cmake --install \$\+PB3\+D\+\_\+\+SRC/\+build --prefix DIR} copies them into {\ttfamily DIR/\+bin}.

A debug build, which has the debug code of PB3D and the runtime checks of the compiler, is made in a second build directory: \begin{DoxyVerb}cmake -S $PB3D_SRC -B $PB3D_SRC/build-debug \
    -DCMAKE_BUILD_TYPE=Debug -DPB3D_ENABLE_DEBUG=ON \
    -DPSPLINE_DIR=$PSPLINE_DIR -DLIBSTELL_DIR=$LIBSTELL_DIR
cmake --build $PB3D_SRC/build-debug -j
\end{DoxyVerb}

\hypertarget{page_installation_installation_tests}{}\doxysection{\texorpdfstring{Tests}{Tests}}\label{page_installation_installation_tests}
The tests are run with CTest from the build directory: \begin{DoxyVerb}ctest --test-dir $PB3D_SRC/build --output-on-failure
\end{DoxyVerb}
 They are grouped in layers, which are selected by their labels, for example with {\ttfamily ctest -\/L unit}:

The tests that run under {\ttfamily mpirun} carry the label {\ttfamily mpi} as well, and {\ttfamily ctest -\/LE mpi} leaves them out. The unit tests can also be built without any of the external libraries: \begin{DoxyVerb}cmake -S $PB3D_SRC -B $PB3D_SRC/build-tests -DPB3D_BUILD_EXECUTABLES=OFF
cmake --build $PB3D_SRC/build-tests -j
ctest --test-dir $PB3D_SRC/build-tests --output-on-failure
\end{DoxyVerb}
 CMake still looks for a C and a C++ compiler in this case, because the project declares these languages. The file {\ttfamily Documentation/\+testing.\+md} of the code describes every test and the recorded eigenvalues.\hypertarget{page_installation_installation_problems}{}\doxysection{\texorpdfstring{Known problems}{Known problems}}\label{page_installation_installation_problems}

\begin{DoxyItemize}
\item With more than one MPI process, a PETSc without MUMPS stops the eigenvalue solver with the message "{}\+Could not locate a solver type for factorization type LU and matrix type mpibaij"{}, which PB3D reports as error code 92 from get\+\_\+solution(). The solver uses shift-\/invert, which needs an LU factorization of a distributed matrix, and the LU factorization of PETSc itself works on one process only.
\item With PETSc 3.\+25, CMake 3.\+31 does not finish the dependency scan of the Fortran header files of PETSc. The scan runs for a quarter of an hour and uses 13 GB of memory before the compilation starts. CMake 4 does not have this problem.
\item On mac\+OS with Open\+MPI 5 from Homebrew, {\ttfamily mpirun} itself can crash while it detects the hardware. PB3D then still runs on one process when the executable is called directly, without {\ttfamily mpirun}, and {\ttfamily ctest -\/LE mpi} skips the tests that use {\ttfamily mpirun}.
\item GNU Fortran 14.\+2 and 14.\+3 compile the bounds check of an array subscript that contains a function call with an array-\/constructor argument wrongly. CMake therefore removes {\ttfamily -\/fcheck=bounds} from the flags of the debug build for every GNU Fortran 14.
\item PB3D stores file names in strings of 120 characters, so the paths of the input and equilibrium files given on the command line must not be longer than that. A symbolic link with a short name helps.
\item A PSPLINE built without the patch of \doxysectlink{page_installation_installation_pspline}{PSPLINE}{2} makes about every other run crash on mac\+OS, with a SIGTRAP or a failure of {\ttfamily H5\+Fcreate}.
\end{DoxyItemize}\hypertarget{page_installation_installation_makefile}{}\doxysection{\texorpdfstring{Legacy Makefile}{Legacy Makefile}}\label{page_installation_installation_makefile}
The code also contains a hand-\/written Makefile, {\ttfamily Makefile.\+legacy}, which is kept for reference. Its paths have to be edited by hand, and neither the tests nor the continuous integration use it. CMake is the supported way to build PB3D.
